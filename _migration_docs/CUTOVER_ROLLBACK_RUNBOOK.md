# 전환(Cutover) 및 롤백 런북

## 전환 절차 (승인 후 실행)
1. 변경 동결 상태 확인 (§MIGRATION_PLAN.md 10단계)
2. 최종 DB 덤프/복원, 최신 파일 동기화 실행
3. 신규 IDC 서버 헬스체크 통과 확인
4. 리버스프록시/DNS를 IDC 서버로 전환
5. 5~10분 내 핵심 페이지·기능 스팟체크
6. 전환 완료 공지

## 롤백 트리거 기준 (아래 중 하나라도 해당 시 즉시 롤백)
- 핵심 페이지(대시보드 3종) 500 오류 또는 로딩 실패
- DB 연결 실패 또는 데이터 불일치 발견
- 인증/접근제어 오작동으로 비인가 접근 가능성 발견
- 응답 지연이 기존 대비 현저히 악화되어 업무 지장

## 롤백 절차
1. 리버스프록시/DNS를 기존 Windows 11 PC(EN-A020) 경로로 즉시 되돌림
2. 기존 Windows 환경에서 통합시스템(허브/UPH 파이프라인)이 여전히 정상 기동 가능한 상태인지 확인 (전환 기간 중에도 기존 환경은 삭제하지 않고 보존해두는 것이 원칙)
3. 전환 이후 신규 서버에서만 발생한 데이터(있다면)를 기존 환경 DB로 역동기화할지 여부 판단 — 데이터 손실 위험이 있으므로 신중히 진행하고 필요 시 사용자 승인 후 처리
4. 장애 원인 조사 후 재전환 일정 재수립

## 원칙
- 기존 Windows 11 환경은 전환 후 일정 기간(예: 2주) 삭제하지 않고 그대로 보존하여 즉시 원복 가능한 상태 유지
- 원복은 "빠르게 되돌릴 수 있음"이 핵심이므로, 전환 전까지 기존 환경의 원본 소스/데이터는 어떤 단계에서도 수정·삭제하지 않는다 (이번 조사부터 지금까지 지켜온 원칙과 동일)
