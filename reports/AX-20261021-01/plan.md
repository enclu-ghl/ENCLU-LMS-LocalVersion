# AX-20261021-01 — 매크로 시작 시 다운로드관리자 창에 붙어 WMS 탭을 닫는 버그 (긴급, Claude 작성)

> 사용자 부재 중 운영 사고로 Claude가 직접 지시서를 작성했다. Codex는 사후 검토만 한다.

## 사고
- 10/20 13:17 매크로가 다운로드 진척도 폴링 중(다운로드관리자 새 창이 열린 상태)에 종료됨(원인 미확인, 오류 출력 없음).
- 10/21 09:58 재시작 시 `_connect_driver()`가 남아 있던 다운로드관리자 창에 붙음 → `wms_handle = driver.current_window_handle`이 다운로드관리자로 잡힘.
- 1회차 `clear_stray_popups()`가 "현재 창 말고 전부 닫기"를 해서 **로그인된 WMS 탭을 닫음**. 디버그 크롬에는 다운로드관리자 페이지만 남음(9222 /json 확인).
- 이후 메뉴 진입 실패 반복, 새로고침도 다운로드관리자 페이지를 새로고침함. 로그인은 보안코드 때문에 자동화 불가 → 사람이 다시 로그인해야 함.

## 수정 범위 (`UPH 시스템/uph_download_macro.py`만)
1. `_select_wms_window(driver)` 추가: 창들 중 제목에 "다운로드관리자"가 없는 첫 창으로 초점 이동·핸들 반환. 없으면 원래 창으로 돌아가고 안내 로그 + `None`.
2. `run_forever` 시작·세션 재연결 시 `wms_handle`을 `_select_wms_window`로 정한다.
3. 매 회차 시작: `wms_handle`이 창 목록에 없으면 다시 찾는다(사람이 탭을 다시 열고 로그인한 경우 재시작 없이 회복).
4. `clear_stray_popups()`의 잔여 창 정리는 **제목에 "다운로드관리자"가 있는 창만** 닫는다.

## 수용 기준
- 다운로드관리자 창에 붙어 시작해도 첫 조회는 WMS 탭에서 실행된다.
- 현재 창이 다운로드관리자여도 WMS 탭은 닫기 시도조차 하지 않는다.
- WMS 탭이 없다가 생기면 다음 회차에 그 탭을 쓴다.
- 기존 테스트 전부 통과, 새 테스트는 수정 전 코드에서 실패.
