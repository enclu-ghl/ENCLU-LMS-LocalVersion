# AX-20261023-01 — UPH 수집 멈춤 알림 (Claude 작성, 사용자 승인 10/23 "로드맵 1단계")

## 배경
10/19~22 수집이 8~16시간씩 멈췄는데 사람이 알아채기 전까지 신호가 없었다. 감시는 Claude 세션이 켜져 있을 때만 가능했다.
알림 채널은 사용자 미정 → 기본은 서버 PC 화면, 메신저는 선택 설정(웹훅 주소)으로 둔다. 새 예약작업·서비스 등록은 하지 않는다(상시 설정 변경 승인 필요).

## 수정 범위 (`UPH 시스템/uph_control_panel.py`만)
1. `StallMonitor`(화면 없는 판단): 매크로 실행 중 마지막 `[DONE]`(없으면 시작 시각)부터 기준 시간(기본 35분, `UPH_ALERT_NO_DONE_MIN`, 최소 10분) 넘으면 한 번 'alert', 이후 새 `[DONE]`이면 'recovered'. 실행 중이 아니면 초기화.
   - 35분 근거: 서버 생성 대기 실측 최대 16.5분(10/22 22:14), 요청당 상한 30분.
2. `ProcessPanel`: 로그 tail에서 `[DONE]`을 보면 `last_done_mono` 갱신, 시작 시 `started_mono`. 예상치 못한 종료 시 `unexpected_exit` 기록.
3. `App._check_alerts()`(매 tick): 예상치 못한 종료는 즉시 1회, 멈춤·회복 알림. 판단 오류는 tick을 멈추지 않음.
4. `App.notify()`: 제어판 빨간 알림 줄, 최상단 알림 창(비모달)+벨, `uph_panel_events.log` 기록, 선택 웹훅(`UPH_ALERT_WEBHOOK_URL`, https만, `{"text":...}` POST, 백그라운드 스레드, 실패 무시).

## 수용 기준
- 정상 회차(35분 내 DONE)에서는 알림 0건, 같은 멈춤에 반복 알림 없음, 회복 후 다음 멈춤은 다시 알림.
- 사람이 종료 버튼/창 닫기로 끈 경우 '예상치 못한 종료' 알림 없음.
- 웹훅 미설정·http·실패 시 전송 안 함/예외 없음.
- 기존 테스트 통과, 새 테스트는 수정 전 코드에서 실패.
