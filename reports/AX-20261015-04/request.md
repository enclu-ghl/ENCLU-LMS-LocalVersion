대상: "UPH 시스템/watchdog_agent.py" (저장소 ENCLU-LMS-LocalVersion). 운영 중인 UPH watchdog 프로세스는 시작 시 코드를 읽으므로, 파일 수정은 UPH 재시작 전까지 운영에 반영되지 않는다.
문제: process_file()이 파일 읽기 실패 시 로그만 남기고 return(442-446), main 루프는 결과와 무관하게 processed_files.add(f)(762-763) → 다운로드 직후 잠금·부분 저장 같은 일시적 읽기 실패 파일은 프로세스 재시작 전까지 다시 처리되지 않음. 회차당 파일 2개(송장입력일/배송일) 중 하나만 실패하면 그 기준 변경분이 누락·지연되고, 실패 파일은 cleanup_old_downloads로 지워질 수 있음.
요구:
1. 읽기 실패 파일은 다음 폴링에서 재시도하되 횟수 제한(영구적으로 깨진 파일이 무한 재시도되지 않게)
2. 재시도 한도를 넘으면 명확한 로그(ERROR)를 남기고 processed로 처리
3. 읽기 이후 단계(DB push 실패 등)의 기존 동작은 바꾸지 않음 — 범위는 읽기 실패만
4. 재시도 중인 파일이 cleanup으로 지워지지 않는지 확인
5. 테스트: 실제 함수에 실패 주입(일시 실패 후 성공 / 영구 실패) — DB·실제 WMS 파일 없이
process_file 반환값을 바꿀 경우 호출부 전부 확인해 줘.
