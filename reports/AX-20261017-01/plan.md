**작업 지시서 — AX-20261017-01**

### 1. 목적 / 완료 조건

UPH 다운로드관리자의 복합 오류 문구를 감지하고 무한 폴링을 차단한다. 실패 후에는 **원래 로그인된 WMS 탭만 보존 → 나머지 창 닫기 → WMS 새로고침 → 다음 회차 재시작** 순서로 복구한다.

완료 조건:

- 상태 셀 첫 줄이 `오류`이면 상세 문구 유무와 관계없이 오류로 판정한다. 기존 2회 연속 확인을 유지하고 상세 내용을 로그에 남긴다.
- 요청별 전체 폴링 상한을 기본 30분으로 두고 환경변수로 조정한다. 상한 도달 시 `False`를 반환한다.
- 복구 과정에서 WMS 탭은 절대 닫지 않는다.
- 실제 브라우저 없는 가짜 driver·시계 테스트로 오류 판정, 시간 상한, 창 정리 순서를 검증한다.
- 코드 검증 완료와 운영 재시작·반영 완료를 구분해서 보고한다.

실측 근거: `UPH 시스템/uph_download_macro.log:54888`에 오류 상태, `:54889`에 reCAPTCHA 상세 문구가 이어진다. `:58253`에는 동일 요청의 **1,686회차·10,986초 경과**가 기록돼 있다.

### 3. 작업 단계

1. **지시서를 대조 검증한다.**  
   현재 diff와 AX-07 구현을 확인하고 `reports/AX-20261017-01/plan-check.md`에 수용·수정·거부 근거를 기록한다.

2. **복합 오류 문구 판정을 수정한다.**
   - 셀 텍스트를 정리하고 `splitlines()`로 첫 줄과 상세 내용을 구분한다.
   - 권장 판정은 **첫 줄을 공백 제거한 값이 `오류`인지 비교**하는 방식이다. `오류 없음`까지 오류로 분류하지 않는다.
   - 동일 요청에서 오류를 2회 연속 확인하면 `False`를 반환한다.
   - 정상 상태나 관측 실패가 끼면 연속 오류 횟수를 초기화해 실제 연속 관측을 보장한다.
   - 상태 셀을 먼저 읽고 오류를 판정한다. 진척도 셀이 없다는 이유로 명확한 오류 판정을 건너뛰지 않도록 한다.
   - 최종 실패 로그에 요청 식별값, 경과 시간, 전체 오류 문구를 포함한다. 줄바꿈은 이스케이프해 한 로그 항목으로 남긴다.

3. **요청별 전체 폴링 상한을 추가한다.**
   - 제안 환경변수: `UPH_DOWNLOAD_POLL_TIMEOUT_SEC`, 기본값 `1800`.
   - 유한한 양수만 허용한다. 잘못된 값은 경고 후 기본값을 적용하며 무제한 대기로 전환하지 않는다.
   - `time.monotonic()`으로 호출별 시작 시각과 마감 시각을 관리한다.
   - 목록 없음, 요청 행 미발견·소실, 셀 읽기 실패 등 **모든 `continue` 경로**에 상한이 적용되게 한다.
   - 남은 시간에 맞춰 대기 시간을 제한하고, 상한 도달 시 사유를 로그에 남긴 뒤 `False`를 반환한다.
   - 기존 요청 행 탐색 제한과 요청 잠금 로직은 유지한다. WebDriver 호출 자체가 멈추는 경우까지 보장되는지는 별도로 확인한다.

4. **WMS 핸들을 기준으로 창 정리를 통일한다.**
   - 보존 대상은 배열의 첫 번째 핸들이나 현재 선택 창이 아니라 저장한 `wms_handle`이다.
   - 복구 전에 WMS 핸들이 존재하는지 확인한다. 없으면 다른 창을 보존 대상으로 대체하거나 닫지 않는다.
   - 핸들 목록 사본을 순회하며 WMS 이외 창만 닫고, WMS로 전환한 뒤 새로고침한다.
   - 이미 사라진 부가 창은 기록하고 계속 처리하되, WMS 소실·세션 단절은 기존 재연결 경로로 전달한다.
   - `clear_stray_popups()`의 현재 창 기준 정리도 함께 보완한다. 다음 다운로드가 시작되기 전에 WMS가 선택됐음을 보장한다.
   - 준비 완료 확인 후 다음 회차를 실행한다. 실패 판정 뒤 남은 조회를 계속하지 않고 복구로 넘어갈지 명시하고, 권장안은 **해당 회차를 실패로 종료한 뒤 기존 90초 간격으로 다음 회차 전에 복구**하는 것이다.

5. **reCAPTCHA 반복 정책을 명확히 한다.**
   - 실제 AX-07 코드는 **3회 후 자동 새로고침만 중단하고 조회 회차는 계속한다**. 전체 매크로 중단과 구분한다.
   - 이번 기본안은 기존 정책을 유지한다. 세 번째 복구 직후 회차도 실패하면 “자동 복구 한도 도달, reCAPTCHA는 수동 확인이 필요할 수 있음”을 한 번 명확히 기록한다.
   - 전체 회차 성공 때만 복구 횟수를 초기화한다. 일부 조회 성공은 초기화 조건으로 삼지 않는다.
   - CAPTCHA 우회·자동 해결은 추가하지 않는다. 반복 시 자동 다운로드 요청까지 멈추는 정책은 아래 질문으로 확정한다.

6. 테스트와 인계 문서를 갱신하고 Codex 검토를 요청한다. 운영 프로세스는 테스트 도중 조작하지 않는다.

### 4. 검증 방법

저장소 루트에서 Claude가 실행한다.

```powershell
py -B -m unittest discover -s "UPH 시스템/tests" -p "test_uph_download*.py" -v
py -B -m unittest discover -s "UPH 시스템/tests" -v
```

필수 검증 표본:

| 구분 | 입력·조건 | 기대 결과 |
|---|---|---|
| 복합 오류 | `오류\nreCAPTCHA 오류입니다. 다시 시도해주세요.` 2회 | `False`, 상세 로그 보존 |
| 오류 연속성 | 오류 → 대기중 → 오류 → 오류 | 마지막 관측에서 실패 |
| 오류 오판 방지 | `오류 없음`, 빈 문자열 | 오류 확정 안 함 |
| 진척도 누락 | 상태는 복합 오류, 진척도 셀 없음 | 오류 확인 규칙 정상 적용 |
| 시간 상한 | 대기 상태를 가짜 시계로 상한까지 진행 | `False`, 실제 30분 대기 없음 |
| 우회 경로 | 목록 없음·잠금 행 소실·셀 예외 반복 | 모두 상한으로 종료 |
| 정상 완료 | 상한 전 완료·100% | 기존 링크 클릭·성공 반환 |
| 창 정리 | WMS·관리자·추가 창, 현재는 관리자 | 부가 창 닫기 → WMS 새로고침 → 조회 순서 |
| 핸들 순서 변경 | WMS가 목록 첫 항목이 아님 | WMS 보존 |
| WMS 없음 | 관리자 창만 존재 | 창 닫기·새로고침 없음 |
| 반복 복구 | 전체 성공 없이 복구 3회 | 네 번째 복구 없음, 안내 1회 |
| 회귀 | 성공 회차·세션 재연결·재확인 회차 | 기존 테스트와 확정한 변경 동작 충족 |

가짜 driver의 `close()`는 WMS가 선택된 상태에서 호출되면 테스트를 즉시 실패시킨다. 실제 driver 연결, 파일 다운로드, 기준선 플래그 쓰기는 mock 처리한다.

운영 검증은 재시작 후 정상 다운로드 파일 생성과 복구 로그를 관찰한다. reCAPTCHA는 인위적으로 유발하지 않는다. **현재 Codex는 테스트 실행·운영 반영을 수행하지 않았다.**

### 5. 위험 요소

- **운영 DB 스키마 변경·대량 쓰기·외부 메시지 발송은 필요 없다.** 이 범위에 포함하지 않는다.
- 잘못된 보존 핸들은 로그인된 WMS 탭을 닫을 수 있다. 기존 `clear_stray_popups()`까지 함께 검증해야 한다.
- 같은 디버그 브라우저의 다른 업무 탭도 닫힐 수 있다. 창 정리는 해당 driver 세션에 한정한다.
- 30분 상한은 성수기 정상 요청도 실패 처리할 수 있다. 창 종료가 서버 작업 취소를 보장하지 않아 재요청과 이전 작업이 겹칠 가능성이 있다.
- 회차 조기 종료는 일부 조회·재확인 누락에 영향을 준다. 기존 재확인 실패 시 3.5일 뒤로 미루는 정책과 충돌 여부를 검증한다.
- 현재 실행 중인 AX-07 프로세스에는 코드 수정이 즉시 반영되지 않는다. **검증 후 운영 매크로 재시작이 필요**하며, 재시작 시점과 적용 결과를 인계에 남긴다.
- 공개 저장소에 실제 업무 로그·접속정보를 추가하지 않는다. commit/push는 기존 규칙에 따라 사용자 확인 후 수행한다.
