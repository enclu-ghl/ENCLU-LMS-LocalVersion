1. **[중간] Git 실패 시 변경 일부가 빠진 상태로 검토를 진행할 수 있음**
   - **위치:** `ax/codex-review.ps1:14`
   - **문제·근거:** Git 명령 3개의 `$LASTEXITCODE`를 확인하지 않습니다. PowerShell 5.1에서는 `$ErrorActionPreference = 'Stop'`만으로 외부 프로그램의 비정상 종료를 차단하지 못합니다. 기준 브랜치 조회가 실패해도 미추적 파일이 있으면 17행 조건을 통과하여 커밋 변경이 빠진 검토를 요청합니다.
   - **확인 방법:** 읽기 전용 명령 `git diff AX_NONEXISTENT_BASE...HEAD`에서 종료 코드 **128**을 확인했습니다. Claude는 Git·Codex 호출을 모의 처리하여, 잘못된 `-Base` 지정 시 Codex 호출까지 도달하는지 확인하십시오.
   - **제안:** 각 Git 명령 직후 종료 코드를 확인하고, 하나라도 실패하면 검토 요청을 중단하십시오.

2. **[중간] 한글 변경사항이 깨진 채 검토 프롬프트에 전달될 수 있음**
   - **위치:** `ax/codex-review.ps1:14`, `ax/codex-review.ps1:36`
   - **문제·근거:** Git 출력을 문자열로 수집하기 전에 출력 디코딩 인코딩을 지정하지 않습니다. 현재 환경의 `[Console]::OutputEncoding.WebName`은 **`ks_c_5601-1987`**이며, 실제 UTF-8 문서 출력도 도구 전달 과정에서 깨지는 것을 확인했습니다. 36행의 `$OutputEncoding` 설정은 이후 Codex에 보내는 인코딩을 지정하므로 이미 깨진 문자열을 복원하지 못합니다. 한글 조건·주석 검토가 부정확해질 위험이 있습니다.
   - **확인 방법:** Windows PowerShell 5.1에서 한글이 포함된 기존 추적 파일을 `git show HEAD:<파일>`로 변수에 수집하고, `Get-Content -Encoding UTF8 <파일>` 결과와 비교하십시오. 이번 변경은 모두 미추적 파일이므로 **실제 한글 diff 전달은 미검증**입니다.
   - **제안:** Git 출력 수집과 Codex 입력 전달에 UTF-8을 일관되게 적용하고, 한글 diff가 원문 그대로 전달되는지 표본 시험하십시오.

**검토 범위:** 지정된 미추적 파일 12개와 필수 문서·프로젝트 가이드를 직접 읽었습니다. `git diff main...HEAD`, `git diff HEAD`는 비어 있으며, `reports/AX-20261014-01/plan.md`는 존재하지 않습니다.
