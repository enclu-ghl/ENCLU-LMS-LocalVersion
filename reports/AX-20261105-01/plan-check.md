## 사실 확인
- PK/UNIQUE: manpower_log(id), uph_historical_summary(id)+UNIQUE(work_date,dong), sales_channel_dong_mapping(id)+UNIQUE(channel_name), alloc_picking_zone(product_code). 동 FK 3개·상품 FK 1개 있음(2026-11-05 E단계).
- manpower_log.event_time = timestamptz, worker_count = integer. **이벤트 종류는 7가지**: 시작·변경·추가·제외·중지·재시작·마감 — 지시서 3-5의 목록(시작·변경·중지·마감·재시작)에 **추가·제외 누락**. 추가/제외도 worker_count에 "결과 총원"을 저장(app.py "➕ 인원 추가"/"➖ 인원 제외")하므로 계산상 변경과 같다.
- 업무일 경계: 전 기록의 KST 날짜 = work_date(불일치 0건), 시각 09:00~23:59 → **자정 넘는 야간 작업 기록 없음**. 질문 4는 데이터로 답함: event_time의 KST 날짜는 work_date와 같아야 한다는 규칙으로 검증.
- 같은 동·같은 시각 이벤트 기존 4쌍 존재 → 지시서대로 새 충돌은 막고 기존은 표시, 정렬은 (event_time, id).
- 요약 수기행 = start_time 있는 6행 / 105행. 분석 병합(app.py "수기 보정 > 실시간 로그 > 자동 요약")도 start_time으로 판정 → correction_locked를 같은 판정에 OR로 추가해야 함(지시서 3-3 맞음).
- 매핑 삭제는 확인 없이 즉시 삭제(app.py 매핑 관리 ② 목록) — 확인 단계 추가.
