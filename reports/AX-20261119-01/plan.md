# AX-20261119-01 WMS에 없는 잔여 송장 제외 기능 (Claude 작성)

> 사용자 요청(2026-11-19): D동 잔여 1건이 WMS에 없는 주문 → 제외. 같은 일이 반복될 수 있어
> '데이터 정정' 화면에서 직접 제외하고 변경 이력에 남는 방식이 필요하다고 판단(사용자 확정).
> 변경 이력 표 제약 교체는 사용자 승인(백업 후 적용).

## 원인 (왜 생기나)
- 수집기(watchdog)는 WMS 파일에서 상태가 **바뀐** 주문만 DB에 쓴다. WMS에서 **사라진** 주문은 감지하지 못해
  `order_status_log`에 '송장' 상태로 남고, 현황판 '총 잔여'(날짜 무관 미배송 전체)에 계속 잡힌다.
- 사례: K2611181666056(믁끄럽, 11-18 09:12 송장) — 09:13 이후 WMS·수집기 캐시 모두 변화 없음, 같은 주문번호 재발행 없음.
  11-19 수동 제외(cs_status='취소' + extra_data 사유, CSV 백업 후).

## 변경
### 운영 DB (`migration_history_osl.sql`, pg_dump 백업 후 적용)
- `data_change_history_table_name_check`에 `order_status_log` 추가.

### `correction_logic.py`
- `remaining_invoices(cur, dong, cancelled_values)`: 현황판 '총 잔여'와 같은 기준(최신 상태·0패딩 무시 주문 키·송장 단위 배송 간주·취소/보류 제외)의 송장 목록.
- `apply_ghost_exclude`: 송장의 '송장' 행 cs_status → '취소'(집계 제외 값), extra_data에 `제외사유`·`제외전_cs_status`·`제외자`·`제외일시`. 이력 UPDATE.
  거부: 조회 뒤 바뀜(StaleError), 배송 행 있음, **같은 주문 키(0패딩 무시)가 다른 송장번호로 배송됨**(11-17 결함 사례), 수정자 없음.
- `excluded_invoices`, `apply_ghost_restore`: 제외 목록·되돌리기(원래 CS 값 복원, 사유 키 제거).

### `app.py` 데이터 정정 → 새 탭 "WMS에 없는 잔여 제외"
- 동 선택 → 총 잔여 송장 표(오래된 것부터, 마지막 수집 시각) → 송장 선택 → "WMS에서 조회되지 않음 확인" 체크 → 제외.
- "제외한 송장 · 되돌리기" 펼침. 변경 이력 대상 이름 "잔여 제외(WMS 미존재)".

## 수집기와의 관계
- 그 주문이 WMS에 다시 나타나 CS·보류·수량이 바뀌면 수집기가 cs_status·extra_data를 실제 값으로 덮는다(실제 값 우선, 이력은 남음).
- 실제로 출고되면 '배송' 행이 새로 생겨 완료로 정상 집계.

## 검토 요청 포인트
- 잔여 기준이 app.py `uph_get_order_counts`와 같은지
- 0패딩 주문 키 배송 확인 쿼리 성능(전체 배송 행 표현식 계산)
- '취소'로 표시하는 방식의 부작용(분석·다운로드에서 취소로 보임)
