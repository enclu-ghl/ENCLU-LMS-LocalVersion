# AX-20261027-01 — 상품별 출고 요약 보존 (로그 정리 전 검증·보충 + 삭제 차단) (Claude 직접)

## 배경
- 웹앱 "로그 보관 및 정리"로 `order_status_log` 월을 지우면 상품별 출고 이력이 사라진다. 챗봇 지표 "분기별 상품별 출고량(송장 수 기준)"과 재고보충계획이 이 이력을 쓴다.
- 이미 `sku_daily_shipment`(work_date, product_code=옵션명, product_name, shipped_qty=수량 합, order_count=`COUNT(DISTINCT invoice_no)` = 그 상품이 들어간 송장 수)가 UPH watchdog에서 1시간마다 최근 3일을 다시 집계해 쌓인다 → **새 테이블 없이 이 테이블을 보존 대상으로 쓴다** (설계 v3.2 B.3.6의 상품별 월 요약을 일 단위로 충족, 분기 = 합산).

## 발견 (2026-10-27 읽기 전용 대조, 9/1~10/27)
- 9/23·10/2·10/8 요약 통째로 없음(송장 997·3,653·2,198건), 9/9~9/11·9/18 늦은 배송확정 미반영(소수). 합계: 빠짐 1,371 · 모자람 33 (상품·날짜 단위).
- 정리 화면은 ④ 파일 확인만 통과하면 삭제가 열렸다 — 상품별 요약 확인 없음.

## 변경
1. `app.py` 공용 함수: `SKU_SUMMARY_SQL`(watchdog과 같은 집계식), `sku_summary_check`(빠짐·모자람·큼 비교), `sku_summary_fill`(같은 집계를 upsert하되 **기존 값보다 작게 덮어쓰지 않음** — 앞서 정리한 달과 걸친 경계 날짜를 남은 원본으로 다시 세면 줄어들기 때문).
2. 정리 화면
   - ① 월 목록에 "정리 가능/보관 기간" 표시, 정리 가능한 달 안내(보관 기간 = 이번 달+지난달). 선택 목록은 정리 가능한 달만 (기존: 이번 달만 제외).
   - ② 아래 "상품별 출고 요약" 확인: 그 달 배송 행의 배송일 범위를 원본과 비교, 다르면 "상품별 요약 채우기" 버튼.
   - ⑤ 삭제는 **② 동별 요약 저장 + ② 상품별 요약 확인 + ④ 파일 확인** 모두 통과해야 열림. 빠진 단계 이름을 안내.
3. 남은 이모지 정리: DB 용량 관리 제목·탭, 매핑 관리 탭 → Material 아이콘.
4. 운영 DB 보충(사용자 승인, 백업 후): 9/1~10/26 `sku_summary_fill` 실행 — 백업 `_local_db/backups/sku_daily_shipment_backup_20261027_103251.csv`(30,823행). 결과 빠짐 0·모자람 0, 원본 송장 313,072건 일치.

## 2차 수정 (Codex 1차 지적 반영)
- [높음] 경계 날짜 누락 → **오래된 달부터 한 달씩만 정리**(선택 목록 = 가장 오래된 정리 가능 달). 확인·채우기를 날짜 구분: 정리 대상 달(intact) = 원본과 **정확히 일치**(덮어쓰기 + 원본에 없는 상품 행 삭제), 앞 달과 걸친 경계 날짜 = 보존값보다 작게 바꾸지 않음. 잔여 위험: 배송 후 1개월 넘게 지나 처음 감지되는 송장(경계 날짜에 새로 추가) — 운영상 거의 없음, 문서화.
- [높음] 동별 요약 행 1건으로 통과 → `dong_summary_check/fill` 추가: 배송일·동 단위로 원본(감지 월이 아닌 배송일 기준 전체)과 대조, 같은 intact/경계 규칙. **수기 입력·보정 행(start_time 있음)은 비교·덮어쓰기 제외**(일자별 UPH 분석에서 실시간 로그보다 우선하는 값). 기존 '요약 만들어 저장'(감지 월 원본만 세서 경계 날짜를 일부만 덮어쓰던 문제)을 대체.
- ② 단계를 "요약 보존 확인" 하나로 합침(상품별 + 동별, 버튼 "요약 채우기"), ⑤ 삭제 = ② 통과 + ④ 파일 확인.
- 격리 PostgreSQL 시험 15/15 통과(경계 110 유지·합포 송장 수·intact 불일치 교정·원본 없는 행 삭제·동별 1건 미통과·수기 행 보존)
