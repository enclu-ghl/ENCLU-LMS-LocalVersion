**AX-20261015-02 — F7 수정 작업 지시서**

### 1. 목적 / 완료 조건

`uph_get_order_counts()` 조회 실패를 정상적인 0건과 구분하고, 실패한 동이 전체 UPH를 낮추는 문제를 수정한다.

완료 조건:

- 일반·모니터/키오스크 모드 모두 조회 실패와 영향 범위를 표시한다.
- 예외 발생 위치·동·기준일을 서버 로그로 남긴다.
- 전체 UPH는 **조회 성공 및 인시 > 0인 동**의 완료건수 합계 ÷ 해당 동의 인시 합계로 계산한다.
- 조회 성공 시 기존 화면·수치·계산 조건을 유지한다.
- SQL·캐시 정책·인원 기록 기능은 변경하지 않는 최소 수정으로 구현한다.

**표시 판단: `counts`의 숫자형 0 대체값 유지 + 명확한 경고 표시를 권고한다.**  
`counts`에 문자열 `"-"`를 넣으면 쉼표 포맷팅뿐 아니라 산술·비교 연산도 깨진다. 실패 여부를 별도 변수로 관리하고, 경고에 **“표시된 0은 실제 집계값이 아님”**을 명시한다.

### 3. 작업 단계

1. **지시서 검증**

2. **실패 상태 분리**
   - 매 실행마다 초기화되는 로컬 변수로 `failed_dongs`, 화면 공통 조회 성공 여부를 관리한다.
   - 두 `except`에서 숫자형 대체값은 유지하되 실패 상태와 로그를 남긴다.
   - 전체 동별 조회와 `target_dong=None` 전체 건수 조회는 독립 호출이다. 한쪽 성공으로 다른 쪽 실패를 덮지 않는다.

3. **전체 UPH 계산 수정**
   - 누적 조건을 `동별 조회 성공 and mh > 0`으로 제한한다.
   - 실패한 동은 완료건수와 인시 모두 UPH 합산에서 제외한다.
   - 실제 누적 인시인 `man_hours_total`은 기존대로 유지한다. UPH 분모 `uph_den`만 제외 처리한다.
   - 실패 동의 상세 표 완료건수·UPH는 표시 단계에서 `—`로 구분한다. 정상 행의 표시·정렬·서식은 유지한다.
   - 실패로 인해 유효한 계산 대상이 하나도 없으면 “UPH 계산 불가”를 명시한다. 정상적인 미시작·0건과 구분한다.

4. **두 모드 공통 경고 추가**
   - 키오스크 분기 이전 공통 영역에 조건부 경고를 둔다.
   - 화면 공통 조회 실패: “출고 현황 조회 실패 — 표시된 0건·0%는 실제 집계값이 아닙니다.”
   - 동별 조회 실패: 실패 동 목록과 “해당 동의 완료건수·인시를 전체 UPH에서 제외”를 표시한다.
   - 개별 동 조회 실패 시 실시간 UPH 0도 유효한 측정값이 아님을 명시한다.
   - 전체 건수만 실패하고 동별 조회가 성공했다면 UPH는 유지한다. 반대 경우에는 전체 건수는 유지하면서 UPH의 제외 범위를 알린다.

5. **예외 로그 추가**

### 4. 검증 방법

운영 DB 중단이나 접속정보 변경 대신 **격리된 실행에서 조회 함수를 모의 처리**한다. 고정 시각·합성 인원 로그를 사용하고 실제 계산·렌더링 코드를 검증한다.

| 조건 | 기대 결과 |
|---|---|
| 모든 조회 성공 | 기존 대비 6개 지표, UPH, 진행률, 상세 표 동일. 새 경고 없음 |
| 성공 응답이 모두 0 | 정상 0건으로 표시. 실패 경고·예외 로그 없음 |
| 동별 조회 하나 실패 | 해당 동 경고·로그 발생. 해당 동 완료건수·인시 모두 전체 UPH에서 제외 |
| 전체 건수 조회만 실패 | 출고 카드·진행률 경고. 성공한 동별 조회 기반 UPH 유지 |
| 동별 실패 + 전체 건수 성공 | 전체 출고 수치 유지. UPH 제외 동 표시 |
| 모든 동별 조회 실패 | UPH 계산 불가 명시. 유효한 0 UPH처럼 안내하지 않음 |
| 개별 동 조회 실패 | 일반·키오스크 모두 경고. 숫자 포맷팅 예외 없음 |
| 실패 후 다음 실행 성공 | 경고·제외 상태 해제. 정상 수치 복원 |
| 성공했지만 인시 0 | 기존처럼 전체 UPH 계산에서 제외 |

합성 계산 예시: A동 100건/2인시, B동 90건/3인시, F동 40건/1인시에서 B동 조회 실패 시 **140건 ÷ 3인시**인지 실제 실행으로 확인한다.

특히 다음을 확인한다.

- 키오스크 진행률 HTML, 카드 `:,`·`:.1f`, 보류 `> 0`, 상세 표의 `None/NaN` 포맷팅 오류 여부.
- 키오스크 후속 조회가 실패해도 앞서 표시한 경고가 유지되는지. 후속 조회까지 보호해야 한다면 해당 조회에 한정한 최소 변경으로 처리한다.
- 실패 주입이 캐시된 성공값에 가려지지 않는지. 캐시 우회·초기화는 격리 테스트에만 적용한다.
- 로그에 실패 문맥은 남고 비밀값은 없는지.

### 5. 위험 요소

- **운영 파일 직접 반영:** push 전에도 실행 앱에 영향을 줄 수 있다. 격리 검증 후 최소 변경만 반영하고 이번 변경분만 복원할 수 있게 준비한다.
- **운영 DB 스키마 변경·대량 쓰기·외부 발송은 필요 없다.** 테스트 중 인원 시작·중지·마감 버튼을 누르면 DB 쓰기가 발생하므로 사용하지 않는다.
- **숫자형 계약 회귀:** `counts`에 `"-"`·`None`을 넣지 않는다. 표시용 대시는 렌더링 단계에만 적용한다.
- **잘못된 분모 제외:** `man_hours_total`까지 줄이면 실제 누적 인시 표시가 바뀐다. UPH 계산 분모와 구분한다.
- **로그 유출·증가:** DB 예외에 비밀정보가 포함될 수 있고 60초 재실행으로 로그가 반복될 수 있다. 마스킹·handler 중복 여부를 검증한다.
- **전면 DB 장애:** 인원 조회 등은 F7 대상 호출보다 먼저 실행된다. 모든 DB 장애에 대한 화면 생존까지 보장한 것으로 보고하지 않는다.
- **검증 한계:** 이번 Codex 작업은 소스·문서·Git 읽기 확인만 수행했다. 실제 DB 장애 재현·화면 실행·로그 수집은 미검증이다.
