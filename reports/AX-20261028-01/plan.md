# AX-20261028-01 — 저장 후 입력칸 초기화 (웹앱 전체)

## 요청
무게구간 계산기를 비롯해 "입력 → 저장" 화면에서 저장이 끝나도 입력값이 남는 곳이 많다. 전체를 찾아 저장 후 초기화되게 고친다.

## 원인
- 입력 위젯 대부분이 키 없이 만들어졌거나, 저장 후 `st.rerun()`만 하고 위젯 상태를 지우지 않았다.
- `st.file_uploader`는 코드로 비울 수 없어 저장 뒤에도 파일이 남는다 → 같은 파일을 다시 반영하면 이중 반영.
- `st.rerun()` 직전 `st.success`는 바로 사라져 저장 완료 메시지가 안 보였다.
- (조사 중 추가 발견) 수정 폼의 키가 고정이라, Streamlit 1.64에서는 수정 대상을 바꿔도 이전 대상의 값이 칸에 남는다
  → 그대로 저장하면 새 대상이 이전 대상 값으로 덮어써진다. 비품 리스트 · 소모품 리스트 · 피킹존 수정에서 재현.

## 방식 (app.py 공통 헬퍼)
- `clear_inputs(*keys)`: 저장 성공 직후 위젯 키를 지움 → 다음 화면에서 기본값으로 다시 그려짐.
- `uploader_key(name)` / `clear_uploader(name)`: 업로더 키에 회차 번호 → 저장 후 번호를 올려 빈 업로드 칸.
- `flash(msg)` / `show_flash()`: rerun 뒤 메뉴 화면 맨 위에 한 번 표시.
- `mp_input_keys(dong_label)`: UPH 인원 패널 입력칸 목록.
- 수정 폼 키에 대상 id(상품코드)를 붙임.

## 검증
- 정적: 구문, CRLF 유지, 새 키 중복 없음, `RerunException`이 `Exception` 하위가 아님(try 안 rerun 안전).
- 동작: 운영 스키마만 복사한 격리 PG(55439)에서 AppTest 25항목 — 저장·초기화·메시지·대상 전환·삭제 체크·UPH 시간 체크.
- 대상 전환 버그는 수정 전 코드로 재현(다른 비품 선택 시 이전 이름 표시) 후 수정 확인.
- 미실행: 파일 업로더 실제 업로드(AppTest 미지원) — 키 회차 변경만 단위 확인.
