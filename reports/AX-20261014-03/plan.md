**3. 작업 단계 — Claude 수행 순서**

1. 지시서를 실제 문서와 대조하고, 수용·수정·거부 및 근거를 보고한다. 보고 파일 저장도 승인된 경로에 한정한다.
2. 기존 설치·연결·샘플 시험 로그를 확보한다. 각 증거에 실행 날짜, 명령, 환경, 종료코드, 결과를 확인한다. 증거가 없으면 해당 항목은 “사용자 제공 정보 / 실행 증거 미확인”으로 기록한다.
3. 세 문서의 변경안을 **파일별로 제시하고 승인된 파일만 수정**한다. 문서 갱신 요청을 모든 파일·설정 변경의 포괄 승인으로 해석하지 않는다.
4. `AX_RULES`에 다음 정책을 반영한다.
   - Codex는 읽기·지시·검토 결과 출력만 수행한다.
   - Claude 수정은 승인된 파일·내용 범위에 한정한다.
   - Hermes는 승인된 호출의 순서를 관리한다. 추가 도구 연결, 권한 확대, 미승인 파일 수정, DB 작업, 외부 발송을 승인할 수 없다.
   - 기존 상호 검증과 수정 반복 최대 2회를 유지한다. 2회 후 남은 문제는 보고하고 중단한다.
   - 이번 작업에서는 commit/push, DB 접근·변경, 외부 발송을 하지 않는다.
5. `HANDOFF`를 다음 상태로 분리한다.
   - WSL Ubuntu 설치: 증거 확인 후 완료 표시.
   - Hermes 설치: 정확한 버전 및 근거 기록.
   - 연결 시험: 실제 성공한 호출 경로만 명시.
   - 합성 샘플 `ax-sample-02`: 26개 테스트 통과의 명령·로그·범위 기록.
   - Hermes 전체 오케스트레이션: **미검증**.
   - 실제 업무 자료를 사용한 첫 과제: 별도 근거 없으면 기존 미완료 유지.
6. `DECISIONS` 상단에 날짜와 TaskId를 붙여 후속 결정을 추가한다. 설치 사실과 권한 정책을 구분하고 기존 이력은 보존한다. 롤백은 이번 문서 변경분만 되돌리는 것으로 제한한다.
7. 변경 검토 후 Claude가 지적을 재검증한다. 승인 범위에서 최대 2회 수정하고, 변경 결과·실행한 확인·미검증 영역을 보고한다.

**4. 검증 방법**

설치 확인은 Claude의 허용된 환경에서 다음 읽기 명령으로 수행한다. 실패하면 우회 설치·설정 변경 없이 결과를 기록한다.

```powershell
wsl --list --verbose
wsl -d Ubuntu -- bash -lc 'cat /etc/os-release; command -v hermes; hermes --version'
```

- Ubuntu 배포판과 WSL 세대를 실제 출력으로 확인한다. Ubuntu 세부 버전은 추정하지 않는다.
- Hermes 출력이 `v0.22.0+102.g5f6d683`과 일치하는지 확인한다.
- 샘플은 기존 테스트 명령과 로그를 우선 확인한다. **실행 명령은 미확인**이므로 임의의 `pytest` 경로를 제시하지 않는다.
- 재실행이 필요하면 합성 입력만 사용하는지, DB·외부 서비스에 접근하지 않는지, 파일 생성 범위가 승인되었는지 먼저 확인한다.
- 테스트 결과의 통과·실패·건너뜀 수와 종료코드를 확인한다. 26개 통과를 운영 데이터 정확성이나 전체 오케스트레이션 성공으로 확대 해석하지 않는다.

문서 수정 후 확인:

```powershell
git diff --check
git diff --name-only
git diff -- docs/AX_RULES.md docs/HANDOFF.md docs/DECISIONS.md
git status --short
```

수작업으로 세 문서의 상태·권한 표현이 일치하는지 대조한다. 스크립트의 읽기 전용 인자는 유지한다. 기존 래퍼는 보고 파일을 생성하므로(`ax/codex-review.ps1:12`), 재검토 실행 시 보고 경로 승인도 확인한다. 운영 DB 쿼리는 필요 없다.
