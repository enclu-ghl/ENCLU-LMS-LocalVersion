## 2. 상세

### F1 (중간) 마이그레이션 검증기가 불일치에도 exit 0
- 위치: `_local_db/verify_migration.py:28` `all_ok = True`, `:45-46` 불일치 시 `all_ok = False`, `:49` 메시지 출력 후 스크립트 종료. `sys.exit(...)` 호출은 `:17`(접속정보 없음) 한 곳뿐.
- 문제: 불일치·조회 실패(`:33-36`, `:40-43`)가 있어도 종료코드는 0. 배치·스크립트·CI에서 종료코드로 성공을 판단하면 **불일치를 성공으로 오판**한다. Supabase 해지(되돌릴 수 없음) 전 검증에 쓰일 도구라 우선순위 1.
- 재현 [모의 재현 — Codex]: DB 접속 없이 엔진을 모의해 원본 행수 2, 대상 1을 반환 → `!!`와 경고 문구 출력, `all_ok=False`인데 종료코드 0. 실제 DB 미사용.
- 제안: 마지막 줄을 `sys.exit(0 if all_ok else 1)`로. HANDOFF 남은 일(`:37`, 비교 대상 URL 별도 입력)과 같은 작업에서 처리 권장.
- 테스트 제안: 모의 엔진으로 일치/불일치/조회 실패 3경우의 종료코드 단위 테스트.

### F7 (낮음~중간) 현황판 집계 예외를 0으로 숨김
- 위치 [소스 확인]: `app.py:3544-3547`(전체 화면 동별 루프), `:3563-3567`(화면 공통) `except Exception:` → 수치를 0으로 대체, 화면 경고·로그 없음.
- 재현 [모의 재현 — Codex]: 실제 try/except 블록을 AST로 추출해 `uph_get_order_counts`가 `RuntimeError`를 던지게 주입 → 6개 수치(overdue·invoiced·delivered·remaining·hold·items) 전부 0, 예외는 삼켜짐. **현재 실제 DB 장애가 있었다는 증거는 아님**.
- 영향: DB 장애·쿼리 오류가 "처리 0건, 진행률 0%"로 표시되어 실제 0과 구분 불가. 전체 화면에서는 해당 동 완료건수가 0으로 빠져 UPH 계산(`:3549-3557`)도 왜곡됨.
- 제안: 예외 시 `st.error`/경고 배지 표시와 로그 기록, 수치는 "-"(미확인)로. 변경은 별도 저장소(`ENCLU-LMS`)라 해당 폴더에서 `git remote -v` 확인 후 진행.

### F6 (낮음~중간) 읽기 실패 파일이 재시도되지 않음

### F5 (낮음, 설정·규칙) 런처의 사설 LAN 기본 주소
- 위치 [소스 확인]: `ENCLU-SCM-ALL-SYSTEM.py:39` 기본 웹 주소 상수(사설 대역 IP + 포트). 값은 이 문서에 옮기지 않음.
