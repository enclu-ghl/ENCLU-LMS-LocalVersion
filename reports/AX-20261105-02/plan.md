# AX-20261105-02 작업 지시서

## 1. 목적 / 완료 조건

비품·소모품·포장재를 구분하고, 포장재의 무게·치수와 재고·주기 체크를 동일 품목으로 연결한다. 제작 완료 박스는 별도 참고 재고로 관리한다.

완료 조건:

- 등록 화면에서 **비품 / 소모품 / 포장재**를 명확히 선택한다.
- 포장재 마스터는 `packaging_materials` 하나만 사용하며, 같은 포장재에 재고 관리 행이 중복 생성되지 않는다.
- 소모품과 포장재만 주기 체크·소비 분석 대상이 된다.
- 체크·수정 화면에서 해당 품목 분석을 확인하고, 저장 후 즉시 갱신된다.
- 분석 화면은 소모품·포장재로 분리하며, 복수 품목 비교와 전체 품목별 실제 입고 간격·사용량 기준 권장 주기를 제공한다.
- 제작 완료 박스는 박스명·파렛트 수량·위치·최소 재고선·제작 기록을 관리한다.
- 기존 메뉴 문자열과 무게구간 계산 결과가 유지된다.
- 운영 반영 전에 백업·복원 확인, 격리 DB 테스트, 운영 시험 실행 후 `ROLLBACK`을 완료한다.

**확인 범위:** 소스와 저장소 문서를 읽었다. 운영 DB에는 접속하지 않았다. 요청의 행 수·FK·소유자 정보는 사용자 제공 현황이며, 실제 열 자료형·제약·권한·현재 행 수는 Claude가 재확인해야 한다.

### 3-2. 데이터 모델

**기본 구조**

- `equipment_items`: 비품 전용으로 유지.
- `supply_items`: 소모품·포장재의 공통 재고 관리 행.
- `supply_check`, `supply_receipt`: 기존 `supply_items.id` FK 유지.
- `packaging_materials`: 포장재 이름·무게·치수의 유일한 원본.
- 제작 완료 박스: 별도 표로 분리하고 공통 소비 분석에서 제외.

`supply_items` 변경안:

| 열 | 규칙 |
|---|---|
| `item_kind` | `consumable` / `packaging`, NOT NULL |
| `packaging_material_id` | 포장재만 사용, `packaging_materials(id)` FK, UNIQUE, 삭제 RESTRICT |
| `is_active` | 기본 true |
| `reorder_qty` | 사용자가 정한 표준 발주량, 양수 또는 NULL |
| `lead_time_days` | 조달 소요일, 0 이상 또는 NULL |

필수 제약:

```sql
CHECK (
  (item_kind = 'consumable' AND packaging_material_id IS NULL)
  OR
  (item_kind = 'packaging' AND packaging_material_id IS NOT NULL)
)
```

`packaging_material_id`의 실제 자료형은 운영 PK와 동일하게 한다.

- 포장재 표시 이름은 항상 JOIN으로 마스터에서 읽는다. `supply_items.name`에 별도 편집 가능한 포장재 이름을 만들지 않는다.
- 기존 `name NOT NULL`이면 포장재의 `name`을 NULL로 허용하고, 소모품만 유효 이름을 요구하는 조건부 CHECK로 전환한다.
- 소모품은 `lower(btrim(name))` 기준 부분 UNIQUE 인덱스로 중복을 막는다. 기존 중복 발견 시 자동 병합하지 않는다.
- 포장재는 마스터 선택 후 재고 관리 정보를 연결한다. 무게 화면에서 신규 등록된 품목도 재고 화면에서 즉시 선택 가능하게 한다.
- 기존 23개 포장재의 **실제 재고는 미확인**이다. 일괄 0재고·가짜 최초 체크를 생성하지 말고, 미연결 상태는 “재고 미설정”으로 표시한다.
- 연결 후 단위는 품목당 하나만 사용한다. 이력 생성 후 단위 변경은 차단한다. 기본안은 기존 흐름에 맞춘 정수 수량이며, 소수 단위 필요 여부는 질문에서 확인한다.

**입고·체크 보강**

- 입고에 기록자 이름과 요청 식별자를 저장한다. 체크에도 중복 제출 방지 식별자를 둔다.
- 입고·체크 인덱스는 `(item_id, occurred_at, id)` 기준으로 준비한다.
- 초기 재고는 최초 체크 기준점으로 저장하고 실제 입고 간격에는 포함하지 않는다.
- 품목 수정에서 재고 직접 덮어쓰기를 제거한다. 재고 변경은 “입고” 또는 “실사 체크”로 구분한다.
- 체크 수정은 이름·사유·수정 전후 값을 감사 이력에 남긴다. 과거 체크나 입고를 수정하면 해당 품목의 후속 구간을 재계산한다.
- 감사 이력 표의 구체 DDL은 기존 자료형 확인 후 작성할 **신설 대상**이다. 이력 있는 품목은 물리 삭제 대신 비활성화한다.

**제작 완료 박스 DDL 제안**

아래는 신규 설계이며 기존 표가 아니다. 같은 박스가 여러 위치에 있으면 위치별 재고 행으로 관리한다.

```sql
CREATE TABLE made_box_stock (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    box_name text NOT NULL CHECK (btrim(box_name) <> ''),
    location text NOT NULL CHECK (btrim(location) <> ''),
    pallet_qty numeric(12,3) NOT NULL DEFAULT 0
        CHECK (pallet_qty >= 0),
    min_pallet_qty numeric(12,3) NOT NULL DEFAULT 0
        CHECK (min_pallet_qty >= 0),
    is_active boolean NOT NULL DEFAULT true,
    updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX made_box_stock_name_location_uq
ON made_box_stock (lower(btrim(box_name)), lower(btrim(location)));

CREATE TABLE made_box_production (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    stock_id bigint NOT NULL REFERENCES made_box_stock(id)
        ON DELETE RESTRICT,
    occurred_at timestamptz NOT NULL,
    pallet_qty numeric(12,3) NOT NULL CHECK (pallet_qty > 0),
    recorder text NOT NULL CHECK (btrim(recorder) <> ''),
    note text,
    request_id uuid NOT NULL UNIQUE,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX made_box_production_stock_time_idx
ON made_box_production (stock_id, occurred_at, id);

CREATE TABLE made_box_stock_adjustment (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    stock_id bigint NOT NULL REFERENCES made_box_stock(id)
        ON DELETE RESTRICT,
    before_qty numeric(12,3) NOT NULL CHECK (before_qty >= 0),
    after_qty numeric(12,3) NOT NULL CHECK (after_qty >= 0),
    recorder text NOT NULL CHECK (btrim(recorder) <> ''),
    reason text NOT NULL CHECK (btrim(reason) <> ''),
    occurred_at timestamptz NOT NULL DEFAULT now(),
    request_id uuid NOT NULL UNIQUE
);

ALTER TABLE made_box_stock OWNER TO enclu_app;
ALTER TABLE made_box_production OWNER TO enclu_app;
ALTER TABLE made_box_stock_adjustment OWNER TO enclu_app;
```

- 制作登録は制作履歴INSERTと再庫加算を同一トランザクションで実行する。
- 制作記録は原則変更不可。誤登録は理由付き在庫調整で補正し、元記録を残す。
- 初期在庫・払出後の残量・訂正は在庫調整として記録し、制作数には加算しない。
- 行ロックまたは更新バージョン照合で同時編集の上書きを防ぐ。
- この在庫を包装材の個数在庫へ自動加算しない。パレットと個数の換算は今回の対象外。

### 3-4. 포장재 이름 참조 보호

현재 `app.py:3325`는 포장재를 직접 삭제하고, `app.py:3393`은 이름만 수정한다. 새 FK만 추가하면 이름 기반 계산 참조는 보호되지 않는다.

- 재고 연결 또는 저장 계산 결과의 이름 참조가 있으면 물리 삭제를 차단한다.
- 저장 계산 결과에 사용된 포장재의 이름 변경은 기본적으로 차단하고 안내한다.
- 무게·치수 수정은 기존 정책대로 유지하되, 저장된 계산 결과를 자동 재계산하지 않는다.
- 두 등록 화면은 동일한 포장재 저장 함수를 사용하고, DB UNIQUE 위반을 사용자 메시지로 처리한다.
- 이름 정규화 중복은 사전 조회하되, 기존 이름을 일괄 변경하지 않는다.

### 3-5. 분석 산식

분석 계산을 UI와 분리하고, 체크·수정·분석 화면이 같은 함수를 사용하도록 한다. 기존 품목별 개별 조회는 선택 대상 전체를 묶어 읽는 방식으로 변경한다.

**공통 기준**

- 저장 시각: `timestamptz`, 화면 날짜: KST.
- 기본 소비 분석: 최근 체크 6건에서 만들어지는 유효 구간. 적용 시작·종료·제외 구간 수를 표시한다.
- 입고 간격 분석: 기본 최근 180일, 기간 선택 제공. 소비 분석과 기간이 다르면 각각 명시한다.
- 수치는 계산 중 반올림하지 않고 표시할 때만 반올림한다.

**사용량·소비 속도**

연속 체크 시각을 `t₀`, `t₁`, 잔량을 `C₀`, `C₁`이라 하면:

```text
R = t₀ < 입고시각 ≤ t₁인 실제 입고량 합계
U = C₀ + R - C₁
D = (t₁ - t₀)의 초 / 86400
일평균 사용량 v = 유효 구간 U 합계 / 유효 구간 D 합계
```

- 첫 체크는 기준점이며 사용량을 만들지 않는다.
- `U < 0`, `D ≤ 0`, 취소·무효 기록은 제외하고 이유를 표시한다.
- 같은 날짜라도 시각이 다르면 실제 경과시간을 사용한다.
- `U = 0`은 유효하다. “사용 관측 없음”과 “데이터 부족”을 구분한다.
- 구간별 일평균의 단순평균을 사용하지 않는다.
- 음수 사용량을 0으로 바꾸지 않는다.
- 체크·입고 저장은 동일 품목을 같은 순서로 잠그고 처리하여 경계 시각의 입고 누락을 방지한다.

**실제 발주 간격의 대용 지표**

발주일이 없으므로 정확한 표시는 **“실제 입고 간격(발주 간격 대용)”**으로 한다.

```text
선택 기간 내 양수 실제 입고를 KST 날짜별로 묶음
입고일 d₁ < … < dₙ
평균 입고 간격 = Σ(dᵢ - dᵢ₋₁) / (n - 1), n ≥ 2
```

- 같은 날 여러 입고는 한 입고일로 취급한다.
- 초기 재고·실사·조정·취소 기록은 제외한다.
- 입고일 2개 미만이면 “산출 불가”.
- 기간 밖 입고일은 분자·분모에 넣지 않는다.
- 입고일 수·간격 수·평균 입고량·마지막 입고일을 함께 표시한다.

**사용량 기준 권장 주기**

표준 발주량 `Q`와 소비 속도 `v`가 모두 양수일 때:

```text
사용량 기준 권장 보충 주기 = Q / v  [일]
```

- `Q`는 사용자가 설정한 `reorder_qty`이다.
- 미설정이면 권장 주기는 “발주량 설정 필요”로 표시한다.
- 관측 평균 입고량을 사용한 `평균 입고량 / v`는 별도 참고값으로만 표시한다.
- `현재 재고 / v`를 권장 주기라고 부르지 않는다.

현재 재고가 마지막 실사 이후 입고만 더해진 장부값임을 명시한다.

```text
장부 재고 커버 일수 = current_qty / v
기준시각 추정재고 =
  max(0, 마지막 실사량 + 이후 입고량 - v × 실사 이후 경과일)
추정 최소선 도달일수 = max(0, (추정재고 - min_qty) / v)
발주 판단선 = min_qty + v × lead_time_days
```

추정재고와 장부재고를 구분하며, 추정치는 DB 현재 재고에 자동 저장하지 않는다. 조달일 미설정 시 확정적인 발주 마감일을 제시하지 않는다. 실제 외부 발주는 수행하지 않는다.

### 3-6. 수량 저장·대량 등록 정리

- 음수·소수점 절삭·NaN·Infinity를 저장 전에 거부한다. 정수 단위는 `int(float())`로 조용히 변환하지 않는다.
- 단건 입고와 엑셀 기존 품목 수량 추가는 모두 **재고 증가 + 입고 기록**을 한 트랜잭션에서 처리한다.
- 신규 품목 초기 재고는 입고 이력이 아닌 최초 기준점으로 처리한다.
- 엑셀은 파일 내 중복·DB 중복·단위 불일치를 먼저 검증한다.
- 대량 반영은 행별 SQL 대신 일괄 INSERT/UPSERT와 일괄 이력 저장으로 처리한다.
- 제출 식별자에 UNIQUE 제약을 두고 더블클릭·rerun·재전송으로 중복 가산되지 않게 한다.
- 복수 품목 체크도 입력 전체를 사전 검증하고 한 트랜잭션에서 저장한다.

### 3-7. 이전·적용·롤백

1. 비품 1행은 변경하지 않는다.
2. 기존 소모품은 기본 `consumable`로 유지한다. 자유 입력 `category='포장재'`만 보고 자동 연결하지 않는다.
3. 예상과 달리 기존 소모품·이력이 있으면 명시적 매핑과 검증 결과를 만든다. 기존 PK와 FK를 유지한다.
4. 포장재 마스터의 ID·이름·무게·치수와 계산 결과는 이전 전후 동일해야 한다.
5. 격리 DB에서 백업 복원·이전·역이전·재적용을 검증한다.
6. 운영 변경 SQL과 영향 행 수를 사용자에게 제시하고 승인받는다. 백업 후 운영에서 `BEGIN → DDL·이전·검증 → ROLLBACK`을 수행한다.
7. 시험 성공 후 별도 적용 트랜잭션을 실행한다. 관련 입력을 잠시 중지하고 잠금 대기 제한을 둔다.
8. 적용 전후 건수·제약·소유자·권한·무게 계산 표본을 확인하고 서비스를 재개한다.

롤백:

- 신규 데이터가 없으면 역마이그레이션으로 추가 구조만 제거하고 코드 변경을 되돌린다.
- 신규 데이터가 있으면 먼저 별도 보관한다. 구 코드가 포장재를 소모품으로 오인하지 않도록 관련 입력을 중지한다.
- 새 데이터가 있는 상태에서 무조건 DROP하거나 전체 DB를 과거 백업으로 덮어쓰지 않는다. UPH 등 다른 시스템의 이후 기록도 손실된다.
- 원상 복구 시 데이터 보존 여부와 재개 절차를 보고한다.

## 5. 위험 요소

- **운영 DB 스키마 변경 필요:** 열·FK·UNIQUE·인덱스·신규 표가 추가된다. 백업·격리 검증·운영 ROLLBACK 시험·사용자 승인 후 적용한다.
- **대량 쓰기 가능:** 초기 연결·이전·엑셀 반영에 발생한다. 건수 사전 제시, 일괄 처리, 중복 방지가 필요하다.
- **무게구간 회귀:** 이름 참조가 있으므로 마스터 이름 변경·삭제가 계산·업로드·저장 결과 선택을 깨뜨릴 수 있다.
- **분석 왜곡:** 입고 누락, 재고 직접 수정, 단위 변경, 과거 이력 수정 후 미재계산을 함께 정리해야 한다.
- **동시 사용자:** 계정이 없어 기록자 이름은 본인 인증이 아니다. 빈 이름은 차단하되 계정 시스템을 이번 범위에 추가하지 않는다.
- **데이터 손실:** 신규 데이터 생성 후 구조 삭제와 전체 DB 복원은 별도 판단이 필요하다.
- **메뉴 호환:** 기존 문자열 변경은 계획하지 않는다. 필요해지면 참조 위치와 영향 범위를 확인하여 사용자 확인을 받는다.
- **외부 발송 불필요:** 실제 발주·구매·메시지·외부 등록은 범위에 없다.
- commit/push와 운영 적용은 `docs/AX_RULES.md`에 따라 사용자 확인 후 수행한다.
