# AX-20261029-01 — 송장 시스템 설계 작업 지시서

## 1. 목적 / 완료 조건

Claude Code는 기존 Streamlit 웹앱에 **일본 배송·KSE OMS 기준 송장 기능을 추가하기 위한 설계안만** 작성한다. 이번 작업에서는 코드 변경, 운영 DB 변경, 실제 API 호출을 통한 등록·삭제, 프린터 출력, WMS 업로드를 수행하지 않는다.

완료 조건은 다음과 같다.

- 기존 기능의 재사용 범위와 송장 기능의 독립 범위를 근거와 함께 명시한다.
- 데이터 모델의 표·컬럼·키·관계, 상태 전이, 화면 흐름을 제시한다.
- **KSE OMS 출력 유지안과 우리 시스템 직접 출력안을 비교하고 선택 조건을 정한다.**
- OMS 삭제·재등록, 합포장, 재출력, WMS 엑셀 반영의 중복·누락 방지 방안을 제시한다.
- 하루 최대 30,000건의 처리·복구·검증 계획을 제시한다.
- 확인된 사실, 설계 제안, 미확인 사항을 구분한다.

현재 운영 DB에 접속하지 않았다. 아래 DB 근거는 코드와 과거 덤프의 정의이며, **현재 운영 스키마와 제약조건은 미확인**이다.

## 3. 작업 단계

### 3-1. 기존 근거와 미확인 항목부터 대조한다

Claude는 위 위치를 재확인하고 지시서 수용·수정·거부 근거를 정리한다. 이번 설계에서 기존 재고할당·주문파일정리·UPH 로직을 수정 대상으로 확대하지 않는다.

재사용 범위는 다음과 같이 정한다.

- **재사용 후보:** 문자열 보존 파일 읽기, 필수 헤더 검증, 오류 차단 후 다운로드, 일괄 upsert 처리 방식.
- **별도 설계:** 주문 식별, OMS 합포 결과, 송장 세대, 출력 이력, 재출력 사유, WMS 반영 결과.
- **읽기 대조 후보:** 기존 배송 상태·출고 요약. 삭제 가능한 원본 로그에 신규 송장 원장을 의존시키지 않는다.

### 3-2. 출력 주체를 비교하고 조건부 권고안을 작성한다

| 방식 | 실현 경계 | 횟수·재출력 통제 | 상대 비용·한계 |
|---|---|---|---|
| **B. KSE OMS가 출력** | 우리 시스템은 동기화·출력 전 검수·결과 기록 | OMS가 출력 이벤트를 제공해야 자동 집계 가능. 제공하지 않으면 수동 기록이며 OMS 재출력을 우리 모달로 강제할 수 없음 | 개발·운영 부담이 가장 작다. 현재 업무 유지에 적합 |
| **A-1. 브라우저 인쇄** | API가 제공하는 PDF·이미지 등을 직원 PC에서 인쇄 | 요청·사용자 확인은 기록 가능. 인쇄창 취소·추가 복사·실물 배출은 별도 문제 | 초기 부담은 비교적 작지만 프린터 선택·배율·여백·횟수 통제가 제한됨 |
| **A-2. 서버 직접 인쇄** | 서버에서 접근 가능한 프린터 큐에 작업 제출 | 큐 제출·상태 기록 가능. 실물 출력 확인 수준은 장비에 따라 다름 | 공유 프린터·드라이버·네트워크 운영 부담. 각 PC의 USB 프린터 접근성은 미확인 |
| **A-3. 로컬 인쇄 에이전트** | 각 출력 PC의 에이전트가 인증된 작업을 받아 지정 프린터로 출력 | 작업 ID·중복 방지·응답 기록을 가장 명확히 설계 가능. 실물 성공은 여전히 별도 정의 필요 | 개발·설치·업데이트·장애 대응 부담이 가장 큼 |

권고는 **B로 동기화·검수 기반을 먼저 설계하고, 직접 출력이 필수라면 A-3을 별도 단계로 분리**하는 것이다. 다만 B만으로 횟수·경고 모달 요구가 충족됐다고 표시하지 않는다.

직접 출력 설계에는 다음을 포함한다.

- Streamlit 서버에서 실행한 인쇄 코드가 직원 PC 프린터를 자동 제어한다고 가정하지 않는다.
- 프린터 프로필: 위치·PC·프린터 식별자·드라이버·용지·방향·배율·DPI·출력 방식.
- 90×60, 60×40, A4 4장형·8장형 각각의 템플릿과 프린터 매핑. A4는 시작 칸·빈 칸·부분 재출력도 정의한다.
- XP-D4601B·XP-DT427B·TTP-384MT의 TSPL/ESC 계열 명령 지원 및 API 결과물 호환성은 **미확인**이다. 원시 출력 가능 여부를 단정하지 않는다.
- 장비 구매 없이 기존 장비로 검증하는 안을 우선 비교한다. 금액 견적은 자료 확보 전 미정으로 둔다.

- 주문상세번호 하나가 상품 여러 행에 반복될 수 있으므로 단독 UNIQUE를 가정하지 않는다. 안정적인 원천 행 키가 없으면 애매한 중복은 검토 대상으로 보낸다.
- OMS 합포 결과를 정본으로 사용한다. 수령인·주소·연락처·판매처 등의 비교는 예상 결과 검증에 사용하고 임의 합치지 않는다.
- 원본 문자열과 정규화 값을 구분한다. 전화번호·우편번호·송장번호의 앞자리 0을 보존한다.
- 주문행과 송장 연결수량의 과다 배정·미배정을 검출한다.
- 삭제된 송장·출력·검수 이력은 물리 삭제하지 않는다. 보존 기간과 개인정보 삭제 정책은 별도로 정한다.

### 3-4. 상태 전이와 동기화 규칙을 작성한다

단일 상태 컬럼에 모든 진행을 넣지 말고 **OMS 상태·검수 상태·출력 상태·WMS 반영 상태**를 분리한다.

기본 흐름:

`주문 수신 → 입력 검증 → OMS 등록 요청/기존 송장 조회 → 발급 확인 → 출력 전 검수 통과 → 출력 요청 → 제출/확인 → WMS 엑셀 생성 → 반영 확인`

예외 흐름:

- **OMS 삭제:** 기존 세대를 비활성화하고 미실행 출력 작업과 검수 승인을 무효화한다.
- **OMS 재등록:** 새 세대를 만들고 이전 송장과 연결한다. 이전 검수·출력·WMS 반영 상태를 자동 승계하지 않는다.
- **취소:** OMS 삭제 사실과 취소 사유를 구분한다. 삭제 사유가 없으면 재등록 대기인지 취소인지 자동 단정하지 않는다.
- **재출력:** 이력이 있는 송장은 경고 모달과 사유 입력을 거친다. 이전·현재 세대의 출력 이력도 함께 표시한다.
- **응답 불명:** API 등록 또는 인쇄 제출 직후 응답이 끊겼으면 조회·대조 후 재시도한다. 자동 재등록·자동 재출력하지 않는다.

동기화 설계에는 다음을 명시한다.

- 웹훅·증분 조회·삭제 이력 제공 여부는 미확인.
- 전체 조회의 모든 페이지가 정상 완료된 경우에만 누락을 삭제 후보로 판단한다. 부분 실패·조회 기간 밖 누락을 삭제로 처리하지 않는다.
- 중복 이벤트, 순서 역전, 지연 응답이 최신 상태를 되돌리지 않게 한다.
- 출력 제출 및 엑셀 생성 직전에 OMS 활성 상태·세대·검수 대상 버전을 다시 확인한다.
- 이미 출력되거나 WMS에 반영된 송장이 삭제되면 경고와 정정 대상 목록을 만든다. 기존 이력을 지워 문제를 숨기지 않는다.

출력 횟수는 **요청 수·제출 수·확인 수·업무 집계 수**를 구분한다. 사유별 집계 제외라도 감사 이력은 남긴다. 사유 정책 변경은 과거 집계에 소급 적용하지 않는다.

### 3-5. 화면 흐름과 외부 경계를 작성한다

화면은 다음 순서로 설계한다.

1. **주문 가져오기:** 양식 선택 → 필수값·중복·수량 검증 → 오류/보류/대상 건수 확인.
2. **OMS 대조:** 발급·미연결·합포 차이·삭제·재등록·동기화 실패 목록.
3. **출력 전 검수:** 프린터·용지·템플릿·주소/상품·시책 확인 → 승인 또는 보류.
4. **출력/재출력:** 대상·위치·프로필 확인 → 재출력 모달 → 진행·실패·불명 목록.
5. **WMS 반영:** 엑셀 미리보기·생성 → 업로드 결과 대조 → 성공/실패 행 확인.
6. **이력:** 주문·송장 세대·검수·출력·삭제·재등록의 연결 조회.

경계 원칙:

- KSE: 발급·합포·삭제·원격 상태의 정본.
- 우리 시스템: 출력 전 검수·작업 이력·동기화·엑셀 생성. 직접 출력 여부는 선택안에 따름.
- 이지어드민: 주문 원천 및 송장번호 반영 결과의 정본.
- 기존 스캔 프로그램: 출력 후 상품 전수 검수 담당. 오류 수신이 가능하면 참고 기록만 저장한다.
- 엑셀 다운로드를 “WMS 업로드 완료”로 처리하지 않는다. 결과 파일·재다운로드 대조 또는 구분된 수동 확인 근거가 필요하다.
- 업로드용 실제 헤더·시트·택배사 코드·행 단위는 **양식 확보 후 확정**한다.

시책 검증은 `docs/DECISIONS.md`의 **2026-08-19 수동 엑셀 체크 결정**을 기본으로 유지한다. 자동 대조 재개가 승인되기 전에는 수동 확인자·시각·규칙 버전·근거만 설계한다.

### 3-6. 규모 대응과 단계별 도입안을 작성한다

- **설계 단계:** API·양식·출력 주체·카운트 의미 확정. 실연동 없이 계약·예외·검증 시나리오 완성.
- **1차 최소 기능:** KSE 일본 배송, 주문 수신·OMS 대조·수동 검수·이지어드민 엑셀·이력. OMS 출력이면 자동 카운트 가능 여부를 명확히 표시.
- **2차 직접 출력:** 선택된 출력 방식 한 곳에서 시험 후 확대. 재출력 모달·사유 정책·중복 방지·불명 작업 복구 포함.
- **3차 확장:** 배송사 어댑터 추가, 배송사별 집계·양식·프린터 매핑, 스캔 오류 수신.

성능 설계:

- 30,000건은 주문행·송장·출력 매수별로 부하를 나누어 산정한다.
- API 속도 제한·일괄 크기·429·부분 실패·재시도 정책은 제공 문서에 맞춘다. 처리시간은 호출 수와 제한값으로 계산하고 임의 수치를 확정하지 않는다.
- DB는 일괄 upsert 또는 staging 후 병합을 사용한다. 행별 INSERT 왕복 반복은 금지한다.
- API 호출 중 DB 트랜잭션을 유지하지 않는다.
- 장시간 작업은 Streamlit 재실행과 분리된 지속 가능한 작업 큐·체크포인트를 설계한다.
- 화면은 서버 조회 필터·페이지 단위 표시·집계 요약을 사용한다. 전체 송장 이미지와 30,000행 위젯을 한꺼번에 생성하지 않는다.

## 4. 검증 방법

이번에는 테스트를 구현하거나 실행하지 않고, 아래 **향후 검증 명세와 기대 결과**를 설계 산출물에 포함한다.

| 단계 | 검증 표본 / 기대 결과 |
|---|---|
| 입력·키 | 앞자리 0, 일본어, HTML `.xls`, 동일 파일 재업로드, 다른 파일의 중복 주문, 동일 주문상세번호의 복수 상품. 누락·중복 배정 없이 출처 추적 |
| OMS 동기화 | 동일 번호 재등록·새 번호 재등록·전체 삭제 후 재등록·부분 조회 실패·중복/역순 이벤트. 과거 이력 보존, 최신 세대만 활성 |
| 검수 | 검수 후 주소·상품·송장·프린터 프로필 변경. 이전 승인 무효화 |
| 출력 | 두 PC 동시 요청·버튼 중복 클릭·브라우저 재실행·큐 제출 후 응답 단절·용지 걸림. 중복 자동 제출 방지, 불명 상태 보존 |
| 횟수 | 사유별 포함/제외·정책 변경·동일 송장 합포·복수 부수. 실출력 이력과 업무 집계가 구분됨 |
| WMS 엑셀 | 합포 복수 주문행·문자열 번호·부분 성공·취소/삭제된 구세대·생성 후 OMS 변경. 잘못된 번호 반영 차단 및 정정 대상 추적 |
| 장비 | 제시된 프린터 모델과 용지 조합별 크기·방향·여백·바코드 판독 시험. 지원 여부 확인 전 호환 판정 금지 |
| 부하·복구 | 1,000건·30,000건 합성 자료, 처리 도중 종료·재개·API 제한. 소요시간·메모리·DB 잠금·조회 응답 측정 |
| 회귀·보존 | 기존 재고할당 결과·`fs_*` 잔량·UPH 집계 불변. 출고 원본 정리 후에도 송장 감사 이력 조회 가능 |

운영 DB의 실제 확인이 필요하면 Claude는 승인된 읽기 전용 연결에서 다음과 같은 **메타데이터 조회**부터 수행하도록 명세한다.

```sql
BEGIN READ ONLY;

SELECT table_name, column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_schema = 'public'
  AND (
    table_name LIKE 'alloc_%'
    OR table_name LIKE 'fs_%'
    OR table_name IN (
      'outbound', 'order_status_log',
      'sku_daily_shipment', 'uph_historical_summary'
    )
  )
ORDER BY table_name, ordinal_position;

ROLLBACK;
```

현재 이 쿼리는 실행하지 않았다. 운영 데이터 내용·현재 제약조건·성능 수치는 미검증이다.

## 5. 위험 요소

- **운영 DB 스키마 변경·대량 쓰기:** 향후 신규 표·인덱스·마이그레이션이 필요하다. 이번 범위에는 실행 권한이 없다. 구현 단계에서 사용자 승인, 백업·복원 및 롤백 계획이 필요하다.
- **외부 전송·상태 변경:** KSE 등록은 수령인·주소·연락처 등의 외부 전송이며 OMS 삭제·재등록도 외부 상태 변경이다. WMS 업로드와 실제 출력도 이번 설계에서 실행하지 않는다.
- **중복 발급·중복 출력:** 외부 처리 성공 후 응답 단절 시 단순 재시도로 중복될 수 있다. 요청키·상태 대조·불명 작업 복구가 필수다.
- **삭제와 취소 혼동:** OMS 전체 삭제를 취소로 확정하면 정상 재등록 주문이 누락될 수 있다.
- **출력 완료 오판:** 브라우저 인쇄 호출이나 큐 접수만으로 실물 배출을 보장하지 못한다. 횟수 정의가 불분명하면 통계와 재출력 정책이 어긋난다.
- **기존 기능 회귀:** 재고할당 합산·장바구니 합포·일괄코드 차감·UPH 완료 규칙을 송장 기능에 혼용하면 수량·출고 실적이 변할 수 있다.
- **비밀정보·개인정보:** API 키는 서버의 `.env`에만 두고 브라우저·엑셀·로그·예외·저장소에 노출하지 않는다. 원본 주문·송장 이미지도 공개 저장소에 넣지 않는다.
- **권한과 책임 추적:** 현재 로그인 부재가 인수인계 문서에 기록돼 있다. 검수자·재출력 승인자를 자유입력 이름만으로 신뢰할지 결정해야 한다.
- **서버 자원 경합:** DB·웹앱·UPH·백업이 같은 PC에 있다. 대량 송장 이미지·인쇄 작업으로 기존 운영을 방해하지 않도록 동시성·보관량을 제한한다.
