# 송장 업로드 파일 표본 구조 (2026-10-30, 사용자 제공)

원본 파일은 저장소에 넣지 않는다(개인정보). 여기에는 구조와 키 관계만 적는다.

- 출처: KSE OMS 목록 다운로드(`<계정ID>_list_<시각>.xlsx`), 시트 1개, 26열, 1행 헤더.
- 사용 방식: **헤더 행을 지우고** 이지어드민 WMS에 송장 등록.
- 표본: 158행 = 송장 79개 × 2행(합포 2건씩), 등록일 1일, 배송타입 `KSE Light`, 판매마켓 1곳.

| 열 | 헤더 | 형태 / 관찰 |
|---|---|---|
| A | 번호 | 정수, 행 순번 |
| B | 등록일 | `YYYYMMDD` 문자열 |
| C | 접수번호 | 영문1+숫자13. 송장과 1:1 |
| D | 배송상태 | 코드(`A10`) |
| E | 배송타입 | `KSE Light` |
| F | 도착지송장번호 | 숫자 12자리 문자열. **송장번호** |
| G | 판매마켓 | 판매처 |
| H | 주문일 | 표본 전부 빈칸 |
| I | 주문번호 | 행마다 고유 → **행 단위 키**(WMS↔OMS 공통키) |
| J | 장바구니번호 | 송장과 1:1 → 합포 단위 |
| K | 상품코드 | 숫자 7자리, 송장마다 1개(행 2개가 같은 값) — 의미 확인 필요 |
| L | 판매자코드 | K와 모든 행에서 동일 |
| M | 상품명(판매마켓대표상품명) | |
| N | 옵션명 | 표본 빈칸 |
| O | 옵션코드 | 바코드13자리+영문1. 한 송장에 서로 다른 옵션 최대 2개 |
| P | 금액 | 소수 2자리 문자열 |
| Q | 수량 | |
| R~U | 받는사람·전화·우편번호·주소 | 개인정보. 송장과 1:1 |
| V~Y | 사이즈·실무게·부피무게·적용무게 | 표본 전부 0 |
| Z | RegionName | `East Japan` / `West Japan` |

키 관계(표본에서 확인): 주문번호 → 송장 1개, 송장 ↔ 접수번호 ↔ 장바구니번호 1:1, 송장 → 받는사람 1개.
모든 값이 문자열로 저장되어 있음(앞자리 0 보존에 유리). 송장번호 앞자리 0은 표본에 없음.

# 이지어드민 주문 원본 → 정리 파일 (2026-10-30, 사용자 제공: 바노바기 2행)

- 원본: 이지어드민 다운로드 `.xls` = **HTML 위장 xls**, 43열(큐텐 양식). 정리: `<날짜>_<브랜드>_정리.xlsx`, 같은 43열·같은 순서.
- 가공 = 파일찢기 `clean_qoo10()` (`주문파일정리 프로그램/file_splitter_gui.py:567`). 표본에서 실제 바뀐 칸은 **옵션정보 → 빈값**뿐
  (판매자옵션코드 빈값 채우기·`+`→`,` 치환은 표본에 해당 행 없음).
- 키 후보: 주문번호(숫자 10자리, 행마다 고유), 장바구니번호(숫자 9자리), **관리번호(숫자 7자리)**, 판매자옵션코드.
- 택배사 열 = `KSE`, 국가 `JP`.

## 사용자 확인 (2026-10-30)
- 이지어드민 송장 업로드: KSE 목록에서 **헤더만 지우고 그대로** 올림. 이지어드민이 정해진 열 위치를 읽어 **관리번호 기준으로 송장번호를 입력**.
- KSE 목록 **K·L열 = 이지어드민 관리번호** (확정).
- KSE 목록 **C열 접수번호 = KSE 송장번호** (확정). F열 도착지송장번호와의 역할 구분은 아래 질문 참고.

## 같은 브랜드 짝 파일 대조 (바노바기: 이지어드민 원본 2행 ↔ KSE 목록 4행, 2026-10-30)
값 일치로 확인한 열 대응:

| KSE 목록 | 이지어드민 원본 |
|---|---|
| L 판매자코드 | **관리번호** (2/2 일치) |
| K 상품코드 | 판매자상품코드 (VIDIVICI 표본에서는 K=L이었음 — 브랜드/판매처마다 다름) |
| I 주문번호 / J 장바구니번호 | 주문번호 / 장바구니번호 (큐텐은 그대로 일치) |
| O 옵션코드 | 판매자옵션코드 |
| H 주문일 | 주문일 |

- **연결키는 L열 판매자코드 = 관리번호**로 잡는다(K열은 판매처에 따라 다름).
- **KSE가 사은품 행을 추가함:** 주문 1건마다 `판매마켓=gift`, 금액 0, 판매자코드 `EVENT_...`, 상품코드 `ITEM_...` 행이 같은 접수번호·주문번호로 붙음.
  → 시책(사은품) 적용 결과로 보이며, 출력 전 시책 검증의 대상 후보. 이 행은 관리번호가 없음.
- 접수번호(C) 1개 = 송장 1개, 같은 송장에 주문행 + 사은품행.

## 시책 (2026-10-30 사용자 확인 + 11월 시책표 docx)
- gift 행 = **KSE에서 기프트 처리한 내역**. 이지어드민에서 적용한 시책은 주문 다운로드에 포함되지 않음(전산 화면에서만 보임).
- 시책표는 회사가 브랜드별 Word 표로 정리: 기간 · 적용처(이지어드민 시책 적용 / 코드별 증정) · 유형(전체·금액별(엔)·수량별·코드별) · 조건 상품명 · 증정품명 · 한정 수량·택1·2개 구매 시 같은 조건.
- 자동 검증 장애: 조건·증정품이 **이름**(코드 아님), 한정 수량 소진, 택1/랜덤, 이지어드민 적용분은 파일에 없음
  → 구조화된 시책 등록(브랜드·기간·유형·조건 코드·증정 코드·한정 수량)과 상품명→코드 매핑이 선행돼야 함.

## KSE API 문서
- `https://kseoms.com/kse_api_guide/<셀러ID>` → 비로그인 시 `/login`으로 이동(2026-10-30 내장 브라우저 확인). 열람은 KSE 로그인 필요.

## KSE 목록과의 연결 (초기 추정 — 위 대조로 갱신됨)
- 이지어드민 **관리번호(7자리)** ↔ KSE **상품코드/판매자코드(7자리)** 로 보임.
- 이지어드민 주문번호(숫자 10자리) ↔ KSE 주문번호(`영문_숫자_숫자`) 는 형태가 달라 직접 키가 아닐 수 있음.
- 두 표본은 브랜드가 달라(바노바기 / VIDIVICI) 실제 일치 여부는 미확인.
