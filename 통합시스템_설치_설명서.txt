====================================================================
ENCLU SCM 통합시스템 설치 및 실행 설명서
====================================================================
이 문서는 메모장으로 여시면 됩니다.
새로운 PC(팀원 PC 등)에 이 통합시스템을 처음 설치할 때 위에서부터
순서대로 따라 하시면 됩니다.


====================================================================
1. 전체 구조 먼저 이해하기
====================================================================

이 통합시스템은 프로그램 하나가 아니라, 여러 개의 파이썬 프로그램을
"ENCLU-SCM-ALL-SYSTEM.py" 라는 허브(런처) 하나가 카드 형태로 묶어서
보여주는 구조입니다.

포함된 프로그램 (지금까지 만든 것 기준):
  1) 박스크기추천 통합 시스템      (main.py)
  2) 상품 매칭 자동화 매크로       (macro_launcher.py + matching_macro.py)
  3) 재고조사 시스템               (웹, 브라우저로 열림)
  4) 무게구간 계산 시스템          (웹, 브라우저로 열림)
  5) UPH 자동 제어판               (uph_control_panel.py
                                     + watchdog_agent.py
                                     + uph_download_macro.py)
  6) UPH 실시간 현황판             (웹, 브라우저로 열림)
  7) 파일 찢기 프로그램            (file_splitter_gui.py)
  8) OMS 송장 출력 제작 프로그램   (준비중, 아직 코드 없음)
  9) 소모품 데이터 작성/분석       (준비중, 아직 코드 없음)

이 중 "웹"이라고 적힌 3개는 브라우저에서 열리는 것뿐이라 이 PC에
따로 설치할 게 없습니다. 나머지(1, 2, 5, 7번)만 이 PC에 파이썬으로
직접 설치/배치해야 합니다.

또 하나 꼭 알아두실 것 -- DB(데이터베이스)가 두 종류입니다:
  - Supabase(클라우드) : UPH 시스템, 파일 찢기 프로그램이 씀
  - 별도 원격 PostgreSQL 서버 : 박스크기추천 시스템(main.py)이 씀
    (이미 서버가 켜져서 돌아가고 있는 상태라, 이 PC에 새로 설치할
     필요는 없습니다. main.py 안에 접속 정보가 이미 코드로 박혀
     있어서 별도 설정 없이 바로 접속됩니다.)

2. 파이썬 설치
====================================================================

이미 만들어진 스크립트들 안에 파이썬 경로가 아래처럼 못박혀
있습니다 (경로가 다르면 실행이 안 됩니다):

  - C:\Users\enclu\AppData\Local\Python\bin\python.exe
    -> UPH 제어판, 파일 찢기 프로그램용

  - C:\Users\admin\AppData\Local\Python\pythoncore-3.14-64\pythonw.exe
    -> 박스크기추천 프로그램용

주의: 두 경로의 사용자 폴더명이 "enclu" 와 "admin" 으로 서로
다릅니다. 이건 예전에 다른 PC에서 테스트했던 흔적일 수 있으니,
새 PC에 설치하실 때는 반드시 실제 이 PC의 Windows 로그인 계정명
(사용자 폴더명)으로 아래 경로들을 전부 맞게 바꿔주셔야 합니다.
(4번 항목에서 정확히 어디를 바꿔야 하는지 설명합니다)

설치 방법:
  1) https://www.python.org/downloads/ 에서 최신 Python 설치
  2) 설치할 때 "Add Python to PATH" 체크박스 반드시 체크
  3) 설치 끝나면 실제로 python.exe가 어디 깔렸는지 확인해야 합니다.
     명령 프롬프트(cmd) 열어서:
        where python
     쳐보면 여러 경로가 뜰 수 있는데, 그 중 진짜 파이썬 경로
     (Microsoft\WindowsApps 안에 있는 건 가짜 스텁이라 무시)를
     찾아서 적어두세요. 보통 아래 둘 중 하나입니다:
        C:\Users\사용자명\AppData\Local\Programs\Python\Python3XX\python.exe
        C:\Users\사용자명\AppData\Local\Python\bin\python.exe

  ※ 주의: "python" 이라고만 쳤는데 아무것도 안 뜨고 "Python" 한 줄만
    찍히고 끝나면, 윈도우 스토어 스텁이 진짜 파이썬보다 먼저 잡힌
    것입니다. 이럴 땐 항상 python.exe의 전체 경로를 직접 써서
    실행하시면 됩니다.
    (설정 > 앱 > 고급 앱 설정 > 앱 실행 별칭에서 python.exe 스위치를
     꺼두면 이 문제 자체가 근본적으로 해결됩니다)

3. 필요한 파이썬 패키지(pip) 한 번에 설치
====================================================================

명령 프롬프트에서, 2번에서 확인한 실제 python.exe 전체 경로로
아래 명령어를 실행하세요 (전체 프로그램에서 필요한 패키지 전부):

"C:\Users\사용자명\AppData\Local\Python\bin\python.exe" -m pip install pandas openpyxl xlrd sqlalchemy psycopg2-binary python-dotenv pykakasi beautifulsoup4 lxml selenium watchdog tkinterdnd2 pymupdf

각 패키지가 어디에 쓰이는지:
  - pandas, openpyxl, xlrd        : 엑셀 파일 읽기/쓰기 (전체 공통)
  - sqlalchemy, psycopg2-binary   : DB 연결 (UPH, 파일찢기, 박스추천)
  - python-dotenv                 : .env 파일 읽기 (UPH, 파일찢기)
  - pykakasi, beautifulsoup4, lxml: 파일찢기 프로그램 전용
    (pykakasi=요미가나 변환 백업용, bs4/lxml=엑셀 파일 파싱용)
  - selenium                      : 자동매칭매크로, UPH 다운로드매크로
  - watchdog                      : UPH watchdog 에이전트
  - tkinterdnd2, pymupdf(fitz)    : 박스크기추천 프로그램 전용

4. 폴더 구조 맞추기 + 경로 수정
====================================================================

아래 구조 그대로 폴더를 만들고 파일을 넣으셔야 합니다
(폴더명은 예시이며, 실제로 지금 쓰시는 폴더명 그대로 유지하시면
 됩니다 -- 중요한 건 "허브 파일이 다른 폴더들을 찾아갈 수 있게
 경로가 서로 맞아야 한다"는 점입니다):

통합시스템\
  ├─ ENCLU-SCM-ALL-SYSTEM.py       <- 허브(런처)
  ├─ ENCLU-SCM-ALL-SYSTEM.bat      <- 더블클릭 실행용
  │
  ├─ 박스추천프로그램\
  │    ├─ main.py
  │    └─ main.bat
  │
  ├─ 자동 매칭 프로그램\
  │    ├─ macro_launcher.py
  │    └─ matching_macro.py         (반드시 같은 폴더에 있어야 함)
  │
  ├─ UPH 시스템\
  │    ├─ uph_control_panel.py
  │    ├─ uph_download_macro.py     (반드시 같은 폴더)
  │    ├─ watchdog_agent.py         (반드시 같은 폴더)
  │    ├─ .env                      (직접 만들어야 함, 아래 참고)
  │    └─ Download the Uph file\    (WMS 다운로드 파일 떨어지는 폴더)
  │
  └─ 주문파일정리 프로그램\
       ├─ file_splitter_gui.py
       └─ .env                      (직접 만들어야 함, 아래 참고)

수정해야 할 경로 -- ENCLU-SCM-ALL-SYSTEM.py 파일을 메모장으로 열어서:

  (1) FILE_PATHS 부분 -- 각 프로그램 파일의 실제 위치로 수정
      "boxscm", "macro", "uph_panel", "file_splitter" 4개 전부
      실제 이 PC의 폴더 경로와 정확히 일치해야 합니다.

  (2) APP_PYTHON 부분 -- 2번에서 확인한 진짜 python.exe 경로로 수정
      "boxscm", "uph_panel", "file_splitter" 3개.
      (여기 경로가 틀리면 카드 눌러도 프로그램이 안 뜹니다)

.bat 파일들도 안에 python.exe 경로가 박혀있으니 (main.bat,
start_panel_bat.bat) 마찬가지로 실제 경로로 맞춰주세요.

5. .env 파일 만들기 (UPH 시스템 폴더, 주문파일정리 프로그램 폴더) (이건호 팀장 DB 사용 중인 상황으로 해당 건은 패스)
====================================================================

메모장으로 새 파일 만들어서 이름을 정확히 ".env" 로 저장
(확장자 없이, 점으로 시작하는 파일명 그대로)

--- UPH 시스템\.env ---
DATABASE_URL=postgresql://... (Supabase 접속정보, 아래 참고)
UPH_WATCH_FOLDER=C:\...\UPH 시스템\Download the Uph file
UPH_CACHE_DB=C:\...\UPH 시스템\uph_agent_cache.sqlite3
UPH_POLL_INTERVAL_SEC=10
UPH_MAPPING_REFRESH_SEC=300

--- 주문파일정리 프로그램\.env ---
DATABASE_URL=postgresql://... (UPH 시스템과 완전히 동일한 값)

DATABASE_URL 값은 어디서 가져오나요?
  -> 기존에 쓰던 다른 PC의 UPH 시스템 폴더 .env 파일을 열어서
     DATABASE_URL= 뒤에 있는 값을 그대로 복사하면 됩니다.
     (같은 Supabase 프로젝트를 팀 전체가 공용으로 쓰는 것이라
      새로 만들 필요 없음)

주의: UPH_WATCH_FOLDER, UPH_CACHE_DB 경로도 실제 이 PC 경로에
맞게 고쳐야 합니다.

6. DB 테이블 준비 (Supabase, 팀 전체 기준 1회만 -- 이미 되어있으면 생략) (이건호 팀장 DB 사용 중인 상황으로 해당 건은 패스)
====================================================================

Supabase는 이미 다른 PC에서 세팅해두신 게 있으면 그걸 그대로
공용으로 쓰시면 되고, 아래는 "완전히 처음부터 새로 판다면"만
해당합니다. 

Supabase SQL Editor에서 순서대로 실행:
  1) UPH 시스템용 테이블 마이그레이션 SQL
  2) migration_file_splitter.sql        (파일찢기 프로그램 테이블)
  3) migration_file_splitter_v2_revert.sql (소진 되돌리기 기능용)
  4) seed_brands.sql (선택, 기존 브랜드 목록 미리 넣기)

박스크기추천(main.py)이 쓰는 원격 PostgreSQL은 이미 서버가 켜져서
동작 중이므로 손댈 필요 없습니다.

7. 실행 방법
====================================================================

가장 간단한 방법: ENCLU-SCM-ALL-SYSTEM.bat 더블클릭
  -> 허브 창이 뜨고, 원하는 프로그램 카드를 누르면 실행됩니다.

개별 프로그램만 켜고 싶을 때는 각 폴더 안의 .bat 파일을
더블클릭하거나, 명령 프롬프트에서:

"진짜파이썬경로\python.exe" "파일명.py"

이렇게 직접 실행해도 됩니다 (지금까지 테스트하실 때 쓰시던 방식).

8. 나중에 코드가 업데이트되면 어떻게 반영하나요
====================================================================

원칙: .py 파일만 새 버전으로 통째로 바꿔치기 하면 됩니다.
      (파일명은 절대 바꾸지 마세요 -- 예: file_splitter_gui.py는
       항상 그 이름 그대로 유지)

  1) 업데이트된 .py 파일을 받는다
  2) 기존 폴더에서 같은 이름의 옛날 파일을 새 파일로 덮어쓴다
     (.env, settings.json, 캐시 DB 파일 등은 절대 안 건드림 --
      이것들은 그대로 둬야 설정/데이터가 안 날아갑니다)
  3) 만약 "DB 테이블 구조가 바뀌었다"는 안내를 받으면, 그때 알려주는
     새 마이그레이션 SQL 파일을 Supabase에서 한 번 실행
  4) 프로그램 다시 실행해서 확인

허브(ENCLU-SCM-ALL-SYSTEM.py) 자체가 업데이트된 경우도 똑같이
파일만 바꿔치기하면 됩니다. FILE_PATHS/APP_PYTHON에 넣어둔 경로는
새 파일에도 그대로 들어있는지 확인만 한 번 해주세요.

9. 새 프로그램을 허브에 추가하고 싶을 때
====================================================================

예: "OMS 송장 출력 제작 프로그램"이 실제로 완성됐다고 가정하면:

  1) 통합시스템 폴더 밑에 새 폴더 만들고 그 안에 .py 파일 넣기
     예: 통합시스템\OMS 송장출력 프로그램\oms_invoice.py

  2) ENCLU-SCM-ALL-SYSTEM.py를 메모장으로 열어서:

     (a) FILE_PATHS 딕셔너리에 한 줄 추가
         "oms_invoice": r"C:\...\OMS 송장출력 프로그램\oms_invoice.py",

     (b) 필요하면 APP_PYTHON에도 한 줄 추가 (특정 파이썬 써야 하면)
         비워두면("") 공통 파이썬을 자동으로 씁니다.

     (c) APPS 리스트 안에서 그 프로그램의 "mode"를 "coming_soon"에서
         "subprocess"로 바꿉니다. (지금은 8, 9번 카드가 "준비중"
         회색으로 표시되도록 coming_soon으로 되어있음)

  3) 저장 후 허브 다시 실행 -> 카드가 정상 색깔로 바뀌고 눌러서
     실행되는지 확인

완전히 새로운 카드(로드맵에도 없던 것)를 추가하고 싶으면, APPS
리스트 안에 있는 카드 하나(예: file_splitter 항목)를 통째로
복사해서 key/title/desc/icon/색상만 바꾸고 FILE_PATHS에도 추가하면
됩니다.

10. 자주 막히는 부분 (문제 해결)
====================================================================

증상: python 명령어 쳤는데 "Python"만 찍히고 아무 반응 없음
원인: 윈도우 스토어 스텁이 먼저 잡힘
해결: python.exe 전체 경로로 직접 실행 (2번 항목 참고)

증상: 카드 눌렀는데 "파일을 찾을 수 없습니다" 에러
원인: FILE_PATHS 경로가 실제 파일 위치랑 다름
해결: ENCLU-SCM-ALL-SYSTEM.py 안의 FILE_PATHS를 실제 경로로 수정

증상: ModuleNotFoundError: No module named '...'
원인: 그 프로그램에 필요한 pip 패키지가 이 PC에 안 깔림
해결: 3번 항목 명령어로 전체 패키지 한 번에 재설치

증상: DB 오류 / DATABASE_URL 관련 에러
원인: .env 파일이 없거나, 파일명/위치/값이 잘못됨
해결: 5번 항목대로 .env 파일이 정확한 위치(해당 .py와 같은 폴더)에
      있는지, 파일명이 정말 ".env"인지(".env.txt"로 저장되는 실수
      흔함) 확인

증상: 프로그램은 켜지는데 브랜드/일괄코드 목록이 안 나옴
원인: DB 연결 실패 (위와 동일)
해결: 콘솔 로그에 뜨는 오류 메시지 확인 후 .env 값 재확인

증상: 일괄코드 소진 관련 이상한 동작
원인: 테스트를 반복하면서 실제 DB 수량이 계속 줄어든 것일 수 있음
해결: 일괄 관리 탭의 "소진 로그"에서 확인 후 필요하면
      "선택 소진 되돌리기"로 복구
