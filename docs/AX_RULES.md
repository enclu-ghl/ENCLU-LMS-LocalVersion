# SCM AX 공통 규칙 (단일 기준)

Claude Code·Codex·Hermes가 모두 이 문서를 같은 기준으로 따른다.
다른 문서와 충돌하면 이 문서가 우선한다. 바꿀 때는 `docs/DECISIONS.md`에 사유를 남긴다.

## 1. 역할 분담

| 담당 | 역할 | 할 수 있는 것 | 하지 않는 것 |
|---|---|---|---|
| 사용자 | 목적·완료 조건 제시, 최종 승인 | commit/push/배포 승인 | — |
| Codex | **지시**(작업 계획서 작성) + **검토**(변경 검토) | 저장소 읽기, `reports/`용 결과 출력 | 파일 수정, DB 쓰기, push |
| Claude Code | **개발** + **Codex 결과 검증** | 승인된 작업 범위 안의 코드 수정, 테스트 실행, 문서 갱신 | 사용자 확인 없는 commit/push/운영 DB 쓰기, 사용자 승인 없는 범위 밖 파일·전역 설정 수정(6장: 파일별 승인) |
| Hermes (연결 시험 단계) | 이미 승인된 Claude·Codex 호출의 순차 진행·기록 | 승인된 호출의 순서 관리, 산출물 읽기 전용 확인 | 승인 범위·도구·쓰기 권한 확대, 미승인 파일 수정, DB 접근, 외부 발송, commit/push |

- Hermes가 끼어도 각 에이전트의 권한은 그대로다(Codex 읽기 전용, Claude 승인 범위 쓰기). Hermes는 새 승인을 대신하지 못한다.
- Hermes 전체 흐름(지시→구현→검토 순차 진행)은 **미검증** — 현황은 `docs/HANDOFF.md`.

## 2. 상호 검증 원칙 (AI 결과는 서로 검증한다)

- **Codex 지시 → Claude 검증 후 착수.** Claude는 지시서를 실제 코드와 대조해
  (존재하지 않는 파일·함수, 이미 해결된 문제, 운영 DB 스키마 변경, 기존 결정과의 충돌)을 확인하고
  `reports/<작업번호>/plan-check.md`에 수용/수정/거부와 근거를 적는다. 거부·수정이 있으면 사용자에게 먼저 알린다.
- **Codex 검토 → Claude 검증 후 반영.** 지적마다 코드·DB·테스트로 재현해 `타당 / 부분 타당 / 근거 없음`을
  판정하고 `reports/<작업번호>/review-check.md`에 남긴다. 그대로 따르지도, 무시하지도 않는다.
- **Claude 구현 → Codex 검토.** 같은 파일을 두 도구가 동시에 수정하지 않는다.
- 수정 반복은 최대 2회. 그래도 남은 문제는 미해결로 사용자에게 보고하고 중단한다.
- **두 AI가 동의했다는 것만으로 정확성이 입증되지 않는다.** 계산은 실제 실행 결과·DB 조회·수작업 표본으로 확인한다.

### 2-1. Codex 사용량이 소진됐을 때 (2026-10-15 사용자 확정)
1. **감지**: `ax\codex-*.ps1`이 종료코드 3과 `CODEX_QUOTA_EXHAUSTED`를 출력한다(사용 한도·rate limit 메시지 감지, 원문은 `reports/<작업번호>/*.log`).
   플러그인(`/codex:review`)에서 같은 메시지가 나와도 동일하게 본다.
2. **중단 후 사용자 확인**: 그 자리에서 작업을 멈추고 사용자에게 알린다. 확인 없이 대체 모드로 넘어가지 않는다.
3. **대체 모드(승인 후)** — 단계와 기록 형식은 그대로, Codex 자리만 바꾼다.
   - 지시서: Claude가 직접 `plan.md`를 쓰고 첫 줄에 `작성: Claude (Codex 대체)`.
   - 검토: 구현한 대화와 분리된 새 컨텍스트로 검토한다 — `devops-review` 에이전트 또는 `/code-review`. `review.md` 첫 줄에 `검토: Claude 대체 검토 (Codex 미검토)`.
   - Claude 검증(`plan-check.md`·`review-check.md`)과 실제 테스트 실행은 생략하지 않는다.
   - 대체 모드로 처리한 작업번호를 `docs/HANDOFF.md`의 "Codex 재검토 대기" 목록에 적는다.
4. **복귀**: 대체 모드 중에는 새 작업을 시작할 때마다 `powershell -File ax\codex-probe.ps1`로 확인한다(종료코드 0 = 사용 가능).
   사용 가능해지면 사용자에게 알리고 원래 흐름으로 돌아가며, "Codex 재검토 대기" 작업은 `ax\codex-review.ps1`로 사후 검토한다.

## 3. 작업 흐름

**요청 창구는 Claude Code 세션(이 저장소 폴더)이다** (2026-10-15 사용자 확정). Claude가 Codex를 불러 지시서·검토를 받는다.
Codex가 Claude를 직접 호출하는 방식은 승인 확인창을 처리할 수 없고 맥락이 끊겨 기본 흐름으로 쓰지 않는다.
Codex 앱에서 계획을 먼저 받은 경우 `reports/<작업번호>/plan.md`로 저장한 뒤 Claude 세션에 "<작업번호> 진행"으로 넘긴다.

1. 사용자: 작업 목적·완료 조건 제시 → 작업번호 부여 (`AX-YYYYMMDD-NN`)
2. Codex 지시: `ax\codex-plan.ps1 <작업번호> "<요청>"` → `reports/<작업번호>/plan.md`
3. Claude: 지시서 검증 → `plan-check.md`
4. Claude: 구현 + 실제 테스트 → `docs/HANDOFF.md` 갱신
5. Codex 검토: `ax\codex-review.ps1 <작업번호>` → `reports/<작업번호>/review.md`
6. Claude: 검토 검증 → `review-check.md` → 타당한 지적만 수정
7. 사용자에게 변경 결과·실행한 테스트/못한 테스트·남은 문제 보고 → commit/push는 확인 후

Hermes가 이 흐름을 순차 진행할 때도 단계·승인 범위는 같다. 2·5단계(Codex)는 읽기 전용, 4·6단계(Claude)는 사용자가 승인한 작업 범위 안에서만 쓴다.

## 4. 데이터·계산 원칙

- 원본에 없는 금액·인원·실적·원인을 사실로 작성하지 않는다. 사실과 추정을 구분한다.
- 모든 지표에 기간·단위·분모·분자·제외 조건을 붙인다.
- 계산은 재현 가능한 코드(Python/SQL)로 하고 원본·산식·단위를 남긴다. AI 설명과 실제 합계를 분리한다.
- 송장 출력/배부 건수와 실제 출고 완료 건수를 구분한다.
- 알려진 UPH 집계 오류가 있는 지표는 수정·대조 확인 전까지 **잠정값**으로 표시한다.
- 재고 순차이(부호 합계)와 절대차이 합계는 별도 지표로 구분한다.
- 스크린샷 OCR 값은 엑셀·원 화면과 대조하며, 미확인 숫자를 확정값으로 채우지 않는다.
- DB 숫자 문제는 추측하지 말고 DB를 직접 조회해 실측 검증한다.

## 5. 업무 초안·등록 원칙

- 자료 검토 후 부족한 내용은 질문 3~5개씩 묶어 확인한다.
- 팀원이 초안을 확인해 등록하고, 팀장은 실행 여부와 자원 배분을 판단한다.
- 개선안: 원인 가설·근거·대안·필요 자원·기대효과·측정 기간·중단 조건을 적는다.
- 인력 추가는 물량·처리능력·실가동 시간·병목 확인 후 산출. 장비 구매는 근거와 미구매 대안을 비교.
- Notion 등 외부 등록은 시험 페이지에서 승인·중복 방지가 검증되기 전까지 하지 않는다.
- 양식은 `docs/REPORT_TEMPLATES.md`.

## 6. 안전·저장소 원칙

- 이 저장소는 **공개**다. IP·계정·비밀번호·DB 접속 URL(계정·비밀번호가 들어간 연결 문자열)·업무 원본 데이터를 커밋하지 않는다
  (CI 비밀 유출 검사가 차단함). 비밀값은 각 폴더 `.env` 또는 저장소 밖 관리자 문서에만 둔다.
- 승인된 작업 범위 안의 로컬 파일 수정은 바로 진행(파일마다 새 승인 불필요), **commit/push는 매번 사용자 확인 후**.
  보호 경로(`~/.claude` 등 전역 폴더 아래 파일)·전역 설정·작업 범위 밖 파일은 파일별로 사용자 승인을 받는다.
- 운영 DB(로컬 PostgreSQL `enclu_scm`) 스키마 변경·대량 쓰기는 사용자 승인 후. 대량 쓰기는 일괄 upsert.
- 자동 배포·실제 Notion 등록·구매·외부 메시지 발송은 에이전트가 단독으로 하지 않는다.
- 전역 설정(`~/.claude`, `~/.codex`, `~/.hermes`) 변경은 최소화하고 변경 시 기록한다.
- 도구 추가는 한 번에 하나씩, 기본 흐름 검증 후. 설치한 도구/버전은 `docs/DECISIONS.md`에 기록.
