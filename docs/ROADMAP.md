## F. SCM팀 챗봇 (신규 제안)

### 목적
SCM 팀원이 대화로 **현황 조회**(UPH·잔여·출고·재고), **업무 기준 확인**(SOP·양식·산식), **보고서 초안**(일일/주간/구매/부재)을 바로 받게 한다.
D절 업무 자동화의 "팀원용 입구" 역할.

### 기능 범위 (단계별)
| 단계 | 기능 | 비고 |
|---|---|---|
| 1 | 정형 조회: "오늘 A동 잔여?", "어제 동별 UPH", "SKU ○○ 최근 7일 출고" | 정해진 쿼리만 실행 — 숫자는 SQL이 계산 |
| 1 | 업무 기준 검색: 보고서 양식, 지표 산식, 운영 절차 | `docs/` 기준 문서·SOP |
| 2 | 보고서 초안: 팀원 입력 + 조회 결과 → 양식(5항목/구매 6항목/일일/주간) 초안, 부족한 정보 3~5개 질문 | AX_RULES 4·5장 그대로 |
| 3 | 등록: 팀원이 확인한 초안만 Notion 등록 | D절 Notion 검증 후 |

### 지켜야 할 원칙 (AX_RULES 기반)
- DB는 **읽기 전용 전용 계정 + 허용된 조회(뷰/쿼리 목록)만**. AI가 임의 SQL을 쓰거나 쓰기 작업을 하지 않는다.
- 숫자는 코드(SQL)가 계산하고 AI는 설명만 한다. 기간·단위·분모·제외 조건을 답에 붙인다. 알려진 UPH 오류 지표는 "잠정" 표시.
- 원본에 없는 사실을 만들지 않는다. 모르면 "확인 필요"로 답한다.
- 접근은 사내망/Tailscale로 제한. 현재 웹앱에 로그인이 없으므로 챗봇 도입 전 **사용자 구분(최소한 이름 선택 또는 간단 로그인)** 필요 — 등록 단계에서는 필수.
- 대화 기록에 개인정보(수령인 이름 등)가 남지 않도록 조회 결과에서 개인정보 열 제외.

### 기술 선택지 — 핵심 제약: **별도 API 예산 없음** 🙋
| 안 | 방식 | 비용 | 장점 | 한계 |
|---|---|---|---|---|
| 1 | **AI 없는 정형 챗봇**: 웹앱 안에 질문 버튼/키워드 → 정해진 조회 실행 | 0원 | 정확, 바로 가능, 기존 웹앱·DB 재사용 | 자유 질문·보고서 문장 작성 불가 |
| 2 | 소액 API 예산으로 Claude 연결(정형 조회 도구 + 문서 검색) | 사용량 비례(예산 승인 필요) | 자유 질문·보고서 초안 품질 높음, 조회 도구 통제 가능 | 예산·키 관리 필요, 개인정보 전송 범위 정해야 함 |
| 3 | 팀 구독형(Claude 팀 플랜 등) Project에 기준 문서를 올려 공유 | 인원당 구독료 | 구축 거의 없음, 문서 기반 Q&A·초안 | 실시간 DB 조회는 별도 연결 필요 |
| 4 | 로컬 AI 모델(Ollama 등) | 0원(하드웨어 별도) | 데이터가 밖으로 안 나감 | **현재 서버 PC(GT 1030 2GB, RAM 16GB)는 부적합** + DB·웹앱·UPH와 자원 경쟁. 전용 GPU PC 필요 |

**권장 진행**: 1단계는 **안 1(비용 0)** 로 정형 조회 챗봇을 웹앱에 붙여 실제 질문 패턴을 모은다 → 그 기록으로 안 2/3의 필요성과 예산을 판단(팀장 결정).
개인 구독(Claude Pro·ChatGPT Plus)은 개인 사용 계정이라 팀 공용 챗봇의 엔진으로 쓰지 않는다.
